# MyCode 结构化系统提示 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。对应 spec.md 的验收标准（AC 编号标注在条目后）。

## 实现完整性

- [ ] 系统提示模块化拼装：输出包含身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出七个模块，按规定顺序出现，模块间空行分隔，尾部为环境信息；相同输入两次构建逐字节一致；七个固定模块总量不超过约 4000 字符（验证：运行 prompt 单元测试套件，顺序/分隔/确定性/长度断言全部通过）——AC1
- [ ] 可选模块扩展点：无内容源时输出不含自定义指令、Skill、长期记忆任何内容；注册一个测试用可选模块后，其内容出现在环境信息之后，且拼装核心代码零改动（验证：prompt 单元测试中的扩展用例通过）——AC2
- [ ] 环境信息：包含工作区根目录、操作系统、Node 版本、当前日期、profile 名称与模型名六个字段（验证：environment 单元测试通过）——AC3
- [ ] 关键规则双重强化：系统提示包含「优先专用工具」「编辑前必先读取」「路径先查证」三条规则；六个工具描述各含与其直接相关的规则表述；工具行为不回归（验证：sections 单元测试通过；六个工具描述可 grep 到规则表述；tools 测试套件通过）——AC7
- [ ] 提醒注入形态：提醒文本被 `<system-reminder>` 标签包裹；execute 模式不生成提醒；plan 模式第 1–5 轮生成序列为完整、精简、精简、完整、精简；精简文案为单行（验证：reminders 单元测试通过）——AC9

## 集成

- [ ] Anthropic 请求映射：请求中 system 为块数组，稳定块带 `cache_control`，环境块不带；工具数组仅末位工具带 `cache_control`；reminder 项渲染为用户角色消息（验证：anthropic provider 单元测试通过）——AC4、AC5
- [ ] OpenAI Chat 请求映射：首条消息为 system 角色且内容为系统提示全文；reminder 项渲染为用户角色消息（验证：openai-chat provider 单元测试通过）——AC4
- [ ] OpenAI Responses 请求映射：请求含 instructions 字段且内容为系统提示全文；reminder 项渲染为用户角色 input（验证：openai-responses provider 单元测试通过）——AC4
- [ ] Runner 集成：每次模型请求都携带同一份冻结的系统提示；reminder 项位于最后一条用户消息之后且顺序保持（验证：runner 单元测试通过）——AC3（会话内稳定）
- [ ] 缓存用量回流：模拟 Anthropic 流携带缓存创建/命中字段后，usage 事件与回合累计用量均包含对应数值（验证：anthropic provider 测试与 runner 测试通过）——AC6
- [ ] 控制器提醒注入：新会话 `/plan` 后连续 5 个回合的请求按完整、精简、精简、完整、精简注入；`/do` 后请求不再携带提醒；再次 `/plan` 后第 1 轮重新注入完整文案（验证：plan-mode 集成测试通过）——AC9、AC10
- [ ] 提醒不持久化：通过仓储读取的持久化消息中不存在任何含 `<system-reminder>` 的正文；界面消息列表不显示提醒（验证：plan-mode 集成测试中的持久化断言通过）——AC8
- [ ] 状态栏显示：模拟用量含缓存命中时状态栏显示 `cache N`，无缓存命中时保持原样（验证：TUI 测试通过）——AC6
- [ ] 旧路径回归：不携带 system 的请求在三个 provider 下都不发送系统提示，行为与 s03 一致（验证：provider 测试中的回归用例通过）——AC4、N5
- [ ] 所有公开接口至少被一个真实调用方使用（验证：编译 + 全部测试通过，无未引用导出）

## 端到端场景

- [ ] E2E-1（Plan 到执行全流程）：新会话输入 `/plan`，提交一个需要读取多文件的任务，观察请求携带系统提示与完整 Plan 提醒，模型只用只读工具并产出计划；输入 `/do` 后请求不再携带 Plan 提醒，回合以全工具模式执行（验证：plan-mode 集成测试端到端用例通过）——AC9、AC10
- [ ] E2E-2（真实缓存验证，人工）：使用支持显式缓存的 Anthropic 协议端点（官方 Anthropic 或确认支持 cache_control 的兼容端点），在同一会话发起多轮请求；第二轮起缓存命中字段大于 0，状态栏可见 cache 数值（验证：人工运行并记录每轮 usage 数值）——AC13
- [ ] E2E-3（定性对比，人工）：按 `tests/acceptance/scenarios.md` 四个场景逐一走查，记录 s04 实际行为并与 s03 对照，形成定性结论（验证：人工填写各场景观察结果）——AC14
- [ ] E2E-4（重启恢复）：Plan 模式会话中重启应用，历史消息完整且无提醒残留；继续发起回合时按轮次规则正常注入提醒（验证：集成测试或人工重启观察）——AC8、AC10
