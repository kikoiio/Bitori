# MyCode 结构化系统提示 Spec

## 背景

MyCode 在 s03 已具备三种模型协议、六个统一工具、持续 Agent Loop、Plan/Do 模式和本地持久化。但发给模型的请求里没有任何系统提示：`ChatRequest` 没有 system 字段，三个 provider 都不发送全局指令，六个工具的描述也只有一句功能说明。

这导致模型只能靠对话内容自行猜测工作方式：不知道应优先使用专用工具而非 shell 命令，不知道编辑文件前必须先读取，不知道当前处于 Plan 模式（只靠工具过滤硬拦），输出风格也不受任何约束——MyCode「能干活」，但干得怎么样全看模型运气。与此同时，请求没有任何缓存策略，每轮都全量重发所有内容，成本和延迟随对话长度持续增长。

## 目标

- 建立结构化的系统提示：七个固定模块（身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出）按优先级拼装，尾部接环境信息；为可选模块（自定义指令、已激活的 Skill、长期记忆）预留扩展点，本步不接入真实内容源。
- 区分稳定与变化内容：固定模块和工具描述走可缓存通道（Anthropic 协议使用显式缓存断点；OpenAI 两协议依赖其自动前缀缓存），环境信息和对话历史走消息通道。
- 关键行为规则（如「优先使用专用工具」「编辑前必须先读取」）在系统提示和相关工具描述中双重强化，提高模型遵守率。
- 运行中通过带特殊标签的请求级消息注入补充指令：不写入持久化、不在界面显示、不会被模型当成用户输入来回复。
- 会话级开关（Plan 模式）的指令按轮次注入：首轮完整、间隔轮次重复完整、其余轮次精简，控制注入频率。
- 通过解析 Anthropic 协议返回的缓存命中字段验证缓存策略实际生效，并准备一组典型场景供人工对比，作为定性评估。

## 功能需求

### 模块化系统提示

- **F1：模块化拼装。** 系统提示由独立模块按优先级拼装而成，顺序固定为：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出，尾部接环境信息。模块之间以空行分隔，整体从前往后拼接。
- **F2：可选模块扩展点。** 自定义指令、已激活的 Skill、长期记忆三类可选模块在拼装顺序中有固定位置（排在环境信息之后）；本步不接入内容源，无内容时这些模块不出现在输出中。后续新增模块只需注册，不改动拼装核心逻辑。
- **F3：环境信息内容。** 环境信息模块包含：工作区根目录、操作系统与平台、Node.js 版本、当前日期、当前 profile 名称与模型名。同一会话内内容稳定。

### 缓存通道

- **F4：三协议系统提示通道。** 三个 provider 都发送同一份系统提示：Anthropic 使用 system 块数组，OpenAI Chat Completions 使用 system 角色消息，OpenAI Responses 使用 instructions 字段；三者语义一致。
- **F5：Anthropic 显式缓存断点。** Anthropic 协议下，工具定义和系统提示中的固定模块标记 cache_control 缓存断点；环境信息模块和对话内容不标记，保证可缓存前缀在会话内稳定。
- **F6：缓存命中可见。** 解析 Anthropic usage 中的缓存创建与缓存命中字段，纳入现有 Token 用量事件和界面展示，使缓存是否生效可观察。

### 关键规则双重强化

- **F7：系统提示中的行为规则。** 工具使用模块明确写出关键规则：优先使用专用工具而非 shell 命令；编辑任何文件前必须先读取该文件；不猜测文件路径，先通过查找确认。
- **F8：工具描述强化。** 六个工具的描述在功能说明之外，补充与该工具直接相关的关键规则（如 edit_file 描述内含「编辑前必须先读取该文件」），与系统提示形成双重强化；描述保持简洁中文，不改变工具的参数、能力和限制。

### 运行时补充指令注入

- **F9：特殊标签注入。** 支持在当轮请求末尾追加带 `<system-reminder>` 标签的用户角色补充消息。这类消息不写入持久化、不在界面消息列表显示；标签内容明确告知模型这是系统补充指令而非用户输入，模型不应对其直接回复。
- **F10：注入确定性。** 注入内容由会话状态（当前模式、轮次序号）确定性生成；会话恢复或历史重放时按相同规则重新生成，不依赖已持久化的提醒内容。

### Plan 模式注入节奏

（一次用户发起的 Agent 回合计为一轮）

- **F11：首轮完整指令。** 会话处于 Plan 模式时，第一轮注入完整规划指令：说明当前只能只读探索、不得修改、最终产出计划。
- **F12：间隔重复完整。** Plan 模式持续期间，每隔 3 轮重复一次完整指令（即第 1、4、7……轮），防止长会话中指令被稀释。
- **F13：其余轮次精简。** 非完整注入轮注入一行精简提醒，仅重申处于 Plan 模式、保持只读。
- **F14：模式切换重置。** 切回执行模式后立即停止注入 Plan 提醒；再次进入 Plan 模式时轮次重新计数。

### 定性评估

- **F15：典型场景集。** 交付一组典型场景文档（覆盖：读取后编辑、专用工具优先、Plan 模式只读约束、输出风格等），每个场景写明操作步骤与观察点，供人工对比 s03 与 s04 的行为差异。

## 非功能需求

- **N1（平台兼容）：** 继续支持 Windows 10/11、Windows Terminal、PowerShell 和项目规定的 Node.js 运行环境，不新增其他平台承诺。
- **N2（三协议统一）：** 系统提示语义、提醒注入行为、Plan 模式节奏在三种协议下一致；显式缓存标记和缓存命中字段仅存在于 Anthropic 协议，这一差异不得改变其他协议的行为。
- **N3（缓存前缀稳定）：** 七个固定模块的内容在同一会话内逐字节稳定——不含时间戳、随机值、逐轮变化的数据；环境信息在会话启动时确定后不再变动，保证可缓存前缀不被破坏。
- **N4（确定性）：** 相同会话状态（模式、轮次、环境）下生成的系统提示和注入内容逐字节一致，可通过快照测试验证。
- **N5（向后兼容）：** s01–s03 的既有能力不回归：Agent Loop、Plan/Do 切换、逐项审批、持久化与恢复、取消、六个工具的行为与限制、三协议流式输出。
- **N6（可测试性）：** 模块拼装、优先级顺序、缓存断点映射、提醒注入、Plan 节奏均可通过模拟模型流和单元测试验证，不依赖真实 API Key 或外部网络；缓存命中验证使用真实 Anthropic 系端点人工进行。
- **N7（界面解耦）：** 系统提示构建与提醒注入不读取或修改 TUI 状态；缓存命中数据通过现有用量事件通道暴露，界面只消费事件。
- **N8（敏感数据）：** 系统提示、环境信息和注入内容不得包含 API Key、令牌或其他密钥材料。
- **N9（提示长度克制）：** 七个固定模块正文总量控制在约 4000 字符以内，在保证规则完备的前提下避免提示膨胀抵消缓存收益。
- **N10（状态留痕）：** s04 的源码注释、项目导读和规划文档遵守现有状态标签规则；被替换的 s01–s03 实现按规则就近保留块注释并写明替换关系，不删除或改写历史说明。

## 不做的事

- 不加载项目指令文件（如 CLAUDE.md、AGENT.md），不实现用户自定义指令的任何内容源；「自定义指令」模块本步只留扩展位置。
- 不实现自动记忆、长期记忆的内容产生、存储或召回；「长期记忆」模块只留扩展位置。
- 不接入真实 MCP、插件或 Skill 系统；「已激活的 Skill」模块只留扩展位置。
- 不做自动化评估（模型评分、LLM judge、评测管线）；定性评估仅依靠人工场景对比。
- 不改变六个工具的业务能力、参数格式、工作区范围、超时或结果上限——只修改描述文本。
- 不改变 s03 的 Plan/Do 语义（工具过滤、计划保存、`/do` 执行），本步只在其上增加提醒注入。
- 不实现条件模块裁剪（按当前可用工具动态改写模块正文）；七个固定模块内容始终完整输出。
- 不将系统提示内容、模块开关或注入节奏开放给配置文件或模型修改；模块内容和节奏规则固定在代码中。
- 不做 OpenAI 两协议的显式缓存控制（协议不支持显式断点），仅依靠其自动前缀缓存，也不宣称对这两协议的缓存验证。
- 不实现上下文压缩、消息淘汰或 Token 窗口管理。
- 不提供系统提示的多语言切换；正文固定为中文。
- 不新增用户命令或界面面板；缓存命中数据并入现有用量展示。
- 不持久化任何注入的提醒消息，也不为其增加存储结构。

## 验收标准

- **AC1（F1、N4、N9）：模块拼装。** 构建系统提示，七个固定模块按「身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出」顺序出现，尾部为环境信息，模块间空行分隔；相同输入两次构建结果逐字节一致；固定模块总量在约定长度内。
- **AC2（F2）：可选模块扩展。** 无内容源时输出不包含可选模块；注册一个测试用可选模块后，其内容出现在环境信息之后，且拼装核心代码零改动。
- **AC3（F3、N3）：环境信息。** 系统提示尾部包含工作区根目录、操作系统、Node 版本、当前日期、profile 名称与模型名；同一会话多轮请求中该部分逐字节一致。
- **AC4（F4）：三协议通道。** 分别检查三个 provider 构造的请求：Anthropic 含 system 块数组、OpenAI Chat 首条为 system 角色消息、Responses 含 instructions 字段；三者承载的系统提示语义一致。
- **AC5（F5）：缓存断点。** Anthropic 请求中工具定义与固定模块带 cache_control 标记；环境信息模块与对话消息不带。
- **AC6（F6）：缓存命中展示。** 模拟 Anthropic 流返回缓存创建/命中数值；用量事件和界面用量展示中包含对应数据。
- **AC7（F7、F8）：双重强化内容。** 系统提示包含「优先专用工具」「编辑前必先读取」「路径先查证」三条规则；六个工具描述各自包含与其直接相关的规则；既有工具行为测试全部通过。
- **AC8（F9、F10）：提醒注入形态。** Plan 模式下构造的请求末尾存在带 `<system-reminder>` 标签的用户角色消息；该消息不出现在界面消息列表中；重启应用后持久化历史中不存在该消息。
- **AC9（F11–F13）：Plan 节奏。** 新会话进入 Plan 模式连续发起 5 轮：第 1、4 轮注入完整规划指令，第 2、3、5 轮注入一行精简提醒。
- **AC10（F14）：模式切换重置。** `/do` 切回执行模式后请求不再携带 Plan 提醒；再次 `/plan` 后第一轮重新注入完整指令。
- **AC11（F15）：场景集交付。** 场景文档存在，覆盖「读取后编辑」「专用工具优先」「Plan 模式只读约束」「输出风格」四类场景，每个场景含操作步骤与观察点。
- **AC12（N5）：回归。** `npm run check` 全部通过（typecheck、lint、既有测试套件、构建）。
- **AC13（F5、F6，人工）：真实缓存验证。** 使用支持显式缓存的 Anthropic 协议端点（官方 Anthropic 或确认支持 cache_control 的兼容端点）在同一会话发起多轮请求，第二轮起缓存命中字段大于 0，且界面可见缓存命中数据。
- **AC14（F15，人工）：定性对比。** 按场景集在 s04 逐一走查并记录实际行为，与 s03 的对应行为作对照，形成定性结论。
