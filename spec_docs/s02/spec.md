# MyCode 工具系统 Spec

## 背景

MyCode 当前是仅支持 Windows 的终端 AI 对话客户端，已经具备 Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions 三种协议的流式响应、连续对话、取消、会话管理和本地持久化，但模型只能生成文本，不能观察或操作当前代码工作区。

本阶段为 MyCode 增加首个工具系统，使模型能够请求读取、创建和修改文本文件、执行命令、查找文件及搜索代码内容。MyCode 负责识别统一的工具调用、取得必要授权、执行工具，并将结构化结果回灌模型。三种协议应呈现一致的工具行为。

## 目标

- 将 MyCode 从纯聊天客户端扩展为能够对当前代码工作区执行实际操作的基础 Agent。
- 提供六个核心工具：读取文件、创建文件、唯一匹配修改文件、执行命令、按模式查找文件、搜索文本内容。
- 让模型通过统一工具描述自主选择工具，不依赖供应商特有行为。
- 对需要副作用的操作逐项取得用户批准，并完整展示、持久保存调用及结果。
- 工具失败、拒绝、超时或输出过大时返回可理解的结构化结果，使模型能够解释或调整。
- 本阶段完成“一批工具调用 → 执行 → 一次结果回灌 → 最终回复”的有限流程，不实现持续自动 Agent Loop。

## 功能需求

- **F1：统一工具能力。** MyCode 向三种模型协议提供一致的工具集合。每个工具都具有名称、用途描述、参数约束和执行能力，模型可以依据这些信息自主选择工具。
- **F2：工具集中登记。** 所有可用工具由单一入口集中登记和查找。提供给模型的工具列表来自该入口，不在各模型协议中分别维护。
- **F3：读取文件。** 模型可以读取当前工作区内的 UTF-8 文本文件。路径越界、文件不存在、内容不是有效 UTF-8 或属于二进制文件时，返回明确的结构化错误。
- **F4：创建文件。** 模型可以在当前工作区内创建新的 UTF-8 文本文件。目标已存在时不得覆盖，并返回明确错误；修改已有文件必须使用修改文件工具。
- **F5：修改文件。** 模型可以提供目标文件、待替换原文和新文本，对现有 UTF-8 文件进行精确替换。原文必须恰好匹配一次；没有匹配或出现多次时不修改文件，并返回包含原因的明确错误。
- **F6：执行命令。** 模型可以请求执行命令。命令从当前工作区启动，并返回退出状态、标准输出和标准错误。确认界面必须提示：获得批准的命令可能访问网络、启动子进程或影响工作区外资源。
- **F7：查找文件。** 模型可以使用路径模式查找当前工作区内的文件。结果不得包含工作区外路径。
- **F8：搜索文本内容。** 模型可以按内容模式搜索工作区内的 UTF-8 文本文件，并获得匹配文件、位置和匹配内容。无法读取的二进制文件不会作为文本搜索。
- **F9：工作区边界。** 读取、创建、修改、查找和搜索工具只能访问 MyCode 启动时的当前工作区及其子目录。绝对路径、路径穿越和解析后落在工作区外的路径均被拒绝。
- **F10：逐项授权。** 读取文件、查找文件和搜索内容可以自动执行。创建文件、修改文件和执行命令必须逐项展示并取得用户批准；同一批调用可部分批准、部分拒绝。
- **F11：拒绝处理。** 用户拒绝某项调用时，该项不得产生副作用。MyCode 为其生成独立的结构化拒绝结果，并与其他已批准或自动执行的结果一起回灌模型。
- **F12：流式工具调用解析。** 三种模型协议返回的工具调用均转换成统一行为。工具名称、调用标识和分片到达的 JSON 参数会被完整拼接；只有参数完整且符合约束后才能进入审批或执行。参数损坏时不得执行工具。
- **F13：首批多工具执行。** 模型首次响应可以请求一批工具。无副作用的读取、查找和搜索调用可以并行执行；创建、修改和命令调用按模型给出的先后顺序串行执行。每项调用都产生独立结果，不因其中一项失败而导致应用崩溃或遗漏其余可执行项。
- **F14：一次结果回灌。** 首批工具全部得到成功、失败、拒绝或超时结果后，MyCode 将整批结果加入对话历史并再次请求同一模型生成最终回复。
- **F15：禁止后续工具链。** 结果回灌后的第二次模型响应可以生成文本答复，但其中出现的新工具调用不得执行。本轮结束，并向用户明确显示已经达到本阶段的工具执行限制。
- **F16：超时处理。** 每个工具使用应用规定的固定超时，模型不能指定、延长或关闭超时。超时后停止该项操作并返回结构化超时结果，不影响其他调用和当前会话。
- **F17：结果大小限制。** 文件内容、文件匹配、文本匹配、标准输出和标准错误均受应用固定大小上限约束。结果超限时返回有限内容，并明确标记已经截断及原始结果规模；模型不能提高或关闭限制。
- **F18：结构化错误隔离。** 路径错误、参数错误、权限不足、目标冲突、匹配失败、进程失败、超时和内部异常均转换为结构化工具结果。单项失败不得导致 MyCode 退出、破坏会话或丢失其他调用结果。
- **F19：界面展示。** TUI 显示每项工具调用的工具名称、关键参数、审批状态、执行状态和结果摘要。用户能够区分等待审批、已批准、已拒绝、执行中、成功、失败和超时状态。
- **F20：持久化与恢复。** 工具调用、参数、审批结果、执行状态和工具结果随会话持久保存。退出并重新启动后仍可查看，后续对话也能按对应模型协议正确恢复这些上下文。
- **F21：三协议一致性。** Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions 均支持上述完整流程。协议差异不得改变工具授权、安全边界、执行规则、错误语义、持久化行为或用户可见状态。

## 非功能需求

- **N1（平台兼容）：** 工具系统继续支持 Windows 10/11、Windows Terminal、PowerShell 和项目规定的 Node.js 运行环境，不引入其他操作系统的兼容承诺。
- **N2（统一性）：** 工具的名称、参数约束、审批规则、结果语义和错误分类在三种模型协议之间保持一致。供应商协议差异不得泄漏到工具实现或 TUI 的核心行为中。
- **N3（工作区安全）：** 所有文件路径在执行操作前都必须按真实文件系统位置验证属于当前工作区，包含符号链接、目录连接点和路径规范化后的情况。文件工具不得借助链接绕过边界。
- **N4（命令风险透明）：** 命令仅保证从工作区启动，不承诺限制其实际影响范围。执行前必须展示足以理解操作的原始命令及风险提示，未经明确批准不得启动进程。
- **N5（副作用控制）：** 创建或修改文件在批准前不得产生临时文件、目录或其他可见副作用；被拒绝、参数无效或匹配不唯一的操作不得改变目标文件。
- **N6（原子性）：** 单次文件创建或修改不得留下部分写入内容。写入失败时，目标应保持原状，或不存在于创建前未存在的残缺文件。
- **N7（响应性）：** 工具执行、文件访问、代码搜索和命令输出读取不得阻塞 TUI 的键盘输入、状态刷新、审批交互或取消退出流程。
- **N8（资源约束）：** 超时、结果上限和输出截断由应用统一控制。处理大文件、大量匹配或持续输出的命令时，内存与持久化数据量必须保持有界。
- **N9（错误隔离）：** 单项工具失败、单个参数流损坏、单次持久化失败或命令异常不得造成其他历史会话损坏，也不得无条件终止整个程序。
- **N10（数据安全）：** 工具调用与结果不得泄漏配置中的 API Key 或环境密钥。用户拒绝的工具不得通过替代执行路径产生同等副作用。
- **N11（持久化一致性）：** 每项调用的审批状态、执行状态和最终结果应一致保存。程序中断后恢复时，不得把未获批准或未完成的调用错误显示为成功。
- **N12（可扩展性）：** 新增工具时无需修改三个 Provider 的核心协议适配；新增 Provider 时无需重写六个工具、授权策略或执行规则。
- **N13（可测试性）：** 工具、注册入口、审批流程、批次调度、结果回灌和三种协议适配均可使用临时工作区和模拟流独立测试，不依赖真实 API Key、外部网络或用户真实文件。
- **N14（可观察性）：** 每项调用都具有稳定标识，并能从界面与持久化记录中关联模型请求、参数、审批决定、执行结果及错误；错误信息应便于用户和模型采取下一步行动。
- **N15（兼容既有功能）：** 未产生工具调用的普通对话、流式文本、extended thinking、取消、会话切换和历史恢复继续保持现有行为。

## 不做的事情

- 不实现可持续多轮执行的自动 Agent Loop；每个用户回合最多执行首批工具并回灌一次。
- 不执行结果回灌后模型再次提出的工具调用。
- 不实现 MCP、远程工具服务器、插件工具发现或运行时安装工具。
- 不允许模型动态创建、注册、修改或删除工具定义。
- 不实现图片、音频、视频、压缩包或其他二进制内容的读取、理解和写入；仅处理 UTF-8 文本。
- 不提供 Base64 二进制读写或多模态模型消息。
- 不允许写文件工具覆盖现有文件；已有文件只能通过唯一匹配替换方式修改。
- 不实现基于补丁格式、正则表达式、行号范围、追加或整文件覆盖的修改模式。
- 不实现文件或目录删除、移动、复制、重命名以及权限修改工具。
- 不实现 Git 专用工具；模型只能在用户逐项批准后通过命令工具调用 Git。
- 不实现命令白名单、容器、虚拟机或其他命令沙箱。
- 不保证已批准命令只能访问当前工作区；命令可能访问网络、启动子进程或影响工作区外资源。
- 不实现工具权限的“本次会话始终允许”、规则记忆、自动批准或批量批准。
- 不支持用户在配置文件中扩展工作区允许目录、工具超时或结果大小上限。
- 不允许模型自行指定超时、输出上限、工作目录或执行权限。
- 不实现多个副作用工具并行执行；它们按模型给出的顺序串行处理。
- 不实现跨多个 MyCode 进程的工具批次协调或文件锁定。
- 不承诺恢复程序中断时尚未完成的工具执行；恢复时只准确显示其未完成状态，不自动重试。
- 不在本阶段加入 token 成本计算、工具调用计费统计或遥测。
- 不扩展 Windows 之外的平台支持。

## 验收标准

- **AC1（F1、F2）— 统一工具清单：** 分别使用 Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions 发起请求；三者收到名称、描述及参数约束一致的六个工具。新增一个测试工具后，只需登记一次，三种协议都能获得该工具。
- **AC2（F3、F9）— 读取文本文件：** 让模型读取工作区内包含中文、换行和代码的 UTF-8 文件，返回内容与原文件一致。尝试读取不存在的文件、二进制文件、工作区外路径、路径穿越目标及链接指向的外部文件时，均不返回文件内容，而是得到明确的结构化错误。
- **AC3（F4、F9、F10）— 创建文件：** 模型请求创建工作区内的新文本文件时，界面先展示目标和内容摘要；批准后文件内容正确，拒绝后文件不存在。目标已存在时不覆盖原内容，并返回明确冲突错误。
- **AC4（F5、F9、F10）— 唯一匹配修改：** 对恰好包含一处目标原文的文件执行修改，批准后仅该处被替换。分别使用零次匹配、多次匹配、工作区外目标、二进制目标及用户拒绝场景，文件均保持原样，并返回可区分的结果。
- **AC5（F6、F10）— 命令执行与确认：** 命令执行前，界面显示原始命令以及可能访问网络、启动子进程或影响工作区外资源的提示。批准后命令从当前工作区启动，并返回退出状态、标准输出和标准错误；拒绝后进程不启动。
- **AC6（F7、F9）— 按模式查找文件：** 使用包含嵌套目录和 Unicode 文件名的临时工作区执行多种路径模式，返回正确且仅位于工作区内的文件；无匹配时返回空结果而非崩溃。
- **AC7（F8、F9）— 搜索文本内容：** 在多个 UTF-8 文件中搜索普通文本和代码片段，结果正确指出匹配文件、位置和内容；二进制文件、不可读取文件及工作区外文件不会作为文本结果返回。
- **AC8（F10、F11）— 逐项与部分授权：** 同一批请求包含多个创建、修改和命令调用时，用户可以逐项批准或拒绝。仅获批项目产生副作用，每个拒绝项目形成独立结果，并与其他项目的结果一起提供给模型。
- **AC9（F12）— 流式参数拼接：** 三种协议分别把一个工具调用的名称、标识和 JSON 参数拆成多个流片段返回；MyCode 在片段完整后得到一次正确调用。缺片、乱序后无效或无法解析的参数不会触发审批与执行，并生成参数错误结果。
- **AC10（F13）— 首批多工具调度：** 首次模型响应同时包含多个只读和副作用调用时，只读调用可以重叠执行，副作用调用严格按模型给出的顺序完成。任一调用失败不阻止其他合法调用获得各自结果。
- **AC11（F14）— 一次结果回灌：** 首批调用全部结束后，成功、失败、拒绝和超时结果按调用标识完整加入同一轮上下文；模型据此生成一条能够引用这些结果的最终文本回复。
- **AC12（F15）— 阻止后续工具链：** 结果回灌后的模型响应再次提出工具调用时，新调用不进入审批、不执行且不产生副作用；界面明确说明本轮已达到工具执行限制，随后允许用户发送下一条消息。
- **AC13（F16）— 固定超时：** 使用不会在应用规定时间内结束的文件操作或命令进行验证；该调用被停止并标记为超时，模型无法通过参数延长限制，其他调用及当前会话仍可继续。
- **AC14（F17）— 结果截断：** 分别读取超大文本文件、制造大量文件匹配、产生大量文本匹配和大量命令输出；返回内容均不超过应用上限，并明确包含已截断标记和原始规模信息。
- **AC15（F18）— 错误结构与隔离：** 分别制造参数无效、路径错误、权限不足、目标冲突、匹配失败、命令非零退出、超时和内部异常；每项都返回可区分的结构化结果，MyCode 不退出，历史会话不损坏，其他调用结果不丢失。
- **AC16（F19）— TUI 状态展示：** 执行包含自动工具、待审批工具、获批工具、拒绝工具、成功、失败和超时结果的批次；用户能在界面中看到每项调用的名称、关键参数、审批状态、执行状态和结果摘要。
- **AC17（F20）— 持久化与恢复：** 完成包含成功、失败、拒绝和超时工具调用的会话后退出并重启；所有调用参数、审批决定、状态和结果仍可查看。继续对话时，模型能依据恢复后的工具历史回答。
- **AC18（F21）— 三协议完整流程一致：** 分别通过三种协议执行同一组读取、创建、修改、命令、找文件和搜索场景；除供应商原始格式外，审批、安全边界、执行顺序、错误分类、历史恢复和用户可见状态一致。
- **AC19（N3、N5、N6）— 边界与文件完整性：** 使用路径穿越、外部链接、拒绝操作、重复匹配、写入中断和权限错误进行验证；文件工具不能越过工作区，失败或拒绝后不留下新目录、残缺文件或部分修改。
- **AC20（N7、N8）— 响应性与资源有界：** 在大文件搜索和持续命令输出期间持续操作 TUI；输入、状态刷新、审批和取消保持可用，进程内存与持久化结果不会随无限输出无界增长。
- **AC21（N9、N10、N11）— 安全与恢复一致性：** 工具结果和错误中不出现配置密钥；拒绝工具不通过替代路径执行。工具执行中强制终止并重启后，已完成状态保持正确，未完成调用不会被显示为成功或自动重试。
- **AC22（N12、N13）— 扩展与可测试性：** 在没有真实 API Key、外部网络和用户真实文件的环境中，六个工具、登记入口、审批、批次调度、结果回灌及三协议适配测试均可运行。增加测试工具无需修改三种协议的核心行为。
- **AC23（N14）— 调用可追踪：** 任一调用都能通过稳定标识关联其模型请求、参数、审批决定、执行状态、结果和错误；同批多个相同工具调用不会相互混淆。
- **AC24（N15）— 既有功能回归：** 不产生工具调用时，三种协议的普通流式文本、Anthropic extended thinking、取消请求、会话切换、退出和历史恢复继续通过既有验收。
- **AC25— 端到端 Agent 场景：** 用户要求模型检查项目、创建一个新文件、修改一个现有文件并运行验证命令；模型在首批调用中组合使用工具，MyCode 对副作用逐项确认、执行并回灌结果，模型生成最终总结。整个过程可在重启后查看，且没有执行第二批工具。
