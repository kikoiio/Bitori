# MyCode Agent Loop Spec

## 背景

MyCode 在 s02 已支持 Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions 三种模型协议、六个统一工具、流式输出、工具结果回灌、逐项副作用批准及本地持久化。但每个用户回合只允许执行首批工具，再请求一次最终回复；如果模型仍需继续读取、修改或验证，只能停止并等待用户再次发消息。

这使 MyCode 具备了工具能力，却还不能根据执行结果自主调整行动。与此同时，现有模型流、工具流程、界面状态和持久化协调集中在聊天控制层，不利于独立运行、测试或复用 Agent 行为。

## 目标

- 为每个用户任务提供持续的 ReAct 循环：模型响应、工具执行、结果回写和再次判断自动重复，直到任务结束。
- 支持模型自然完成、20 轮上限、用户取消、连续三轮只调用未知工具、模型流错误等明确停止条件。
- 通过统一异步事件流输出文本、工具调用、工具结果、Token 用量和执行进度，使 Agent 行为不依赖具体界面。
- 每次模型迭代形成独立助手消息，实时展示并分别持久化；同时保存单次迭代和整个 Agent 回合的 Token 用量。
- 同一响应包含多个工具调用时，连续只读工具可以并发；副作用工具形成顺序安全屏障，逐项批准并串行执行。
- 提供按会话持久化的 Plan Mode：`/plan` 切换为仅可使用只读工具的持续模式；`/do` 恢复全部工具并立即执行最近完成的计划。
- 保持 s02 已有三协议一致性、工作区边界、工具限制、错误隔离、逐项批准和会话恢复能力。

## 功能需求

- **F1：自主循环。** 用户提交普通任务后，MyCode 自动重复“请求模型、接收响应、执行工具、回写结果”，无需用户逐轮催促。
- **F2：迭代消息。** 每次模型请求对应一条独立助手消息。消息在流式接收时实时更新，并在该次迭代结束、取消或失败时保存准确终态；纯工具调用响应即使没有正文也保留记录。
- **F3：自然完成。** 某次模型响应不再请求任何工具时，视为任务自然完成，并以该次响应作为本回合最终回复。
- **F4：迭代计数。** 一次模型流响应计为一次迭代；工具调用数量不单独增加迭代次数。每个用户任务最多进行 20 次模型迭代。
- **F5：迭代上限。** 如果第 20 次模型响应仍请求工具，这批新调用不得执行；MyCode 保存调用及上限错误，终止本回合并明确显示停止原因。
- **F6：用户取消。** 用户取消时，MyCode 中止正在进行的模型流和可中断工具，取消待审批及尚未开始的调用，保留已经完成的消息和工具结果，不再开始下一次迭代。
- **F7：未知工具保护。** 某次迭代只请求未注册工具时，MyCode 为每项调用生成结构化错误并回写模型。连续三次出现这种迭代后停止；任何已注册工具调用都会把连续计数清零。
- **F8：模型流错误。** 模型流显式报错或未产生正常结束事件便中断时，本回合立即停止且不自动重试；已经收到的文本、思考内容、用量和工具调用分片按实际状态保留。
- **F9：统一异步事件。** Agent 运行期间按发生顺序产生文本、思考内容、工具调用、工具结果、Token 用量、审批等待、进度变化和终止结果事件。事件携带稳定的回合、迭代和工具调用关联信息，不依赖具体界面。
- **F10：流式双路收集。** 文本和思考内容到达时立即作为事件输出，同时被完整累积；模型流结束后，Agent 能使用完整响应判断是否存在工具调用、结束原因及下一步动作。
- **F11：进度信息。** 运行过程中可观察当前迭代数、20 轮上限、当前阶段、工具批次进度及最终停止原因，使界面可以只根据事件展示状态。
- **F12：安全分批。** 同一模型响应中的工具调用按原始顺序处理：连续只读调用组成可并发批次；写入或命令调用构成安全屏障，等待前批结束并逐项批准、串行执行；屏障后的调用随后继续。
- **F13：批次隔离。** 某项工具失败、超时、被拒绝、参数无效或名称未知时，其他仍可执行调用继续按调度规则完成。回写模型的结果按原始调用顺序排列。
- **F14：结果驱动调整。** 每批工具全部进入终态后，结果被加入模型上下文并自动发起下一次迭代；模型可以依据成功、失败、拒绝、超时和截断结果调整后续行动。
- **F15：Plan Mode 切换。** `/plan` 将当前会话切换为 Plan Mode，但自身不请求模型；在该模式下，后续普通任务仍运行完整 Agent Loop，但只向模型开放只读工具。
- **F16：Plan Mode 保护。** Plan Mode 中即使模型请求已注册的写入或命令工具，也不得执行；MyCode 返回“当前模式不可用”的结构化结果。此情况不计为未知工具迭代。
- **F17：计划执行。** 成功自然完成的 Plan Mode 任务成为该会话的最新计划。`/do` 切换回全工具模式，并立即以最新计划及现有会话上下文启动执行；没有可用计划时不请求模型并明确提示。
- **F18：模式持久化。** 每个会话分别保存当前模式和最新可执行计划。切换会话或重启 MyCode 后恢复；`/do` 启动执行后，会话继续保持全工具模式。
- **F19：Token 用量。** 每条助手迭代消息保存自身输入、输出 Token 用量；Agent 回合同时实时累计并展示全部迭代的输入、输出 Token 总量。
- **F20：现有批准流程。** 只读工具自动执行；写入和命令继续沿用 s02 的逐项 `Y/N` 批准。等待批准期间 Agent Loop 暂停，决定完成后自动继续。
- **F21：三协议一致性。** Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions 均支持相同循环、事件、停止条件、Plan Mode、工具调度和持久化行为。

## 非功能需求

- **N1（平台兼容）：** 继续支持 Windows 10/11、Windows Terminal、PowerShell 和项目规定的 Node.js 运行环境，不新增其他平台承诺。
- **N2（界面解耦）：** Agent 核心只通过统一输入和异步事件表达行为，不读取或修改 TUI 状态；替换为其他事件消费者时，无需改变循环、停止或工具调度规则。
- **N3（响应性）：** 模型文本和思考内容到达后应立即对事件消费者可见；模型等待、工具执行、持久化和审批不得阻塞键盘输入、取消操作或界面刷新。
- **N4（事件一致性）：** 同一运行中的事件不得无故丢失或重复。回合、迭代、工具调用和终止事件可以通过稳定标识关联，最终状态必须与实际执行结果一致。
- **N5（有界运行）：** 单个用户任务受 20 次模型迭代限制；工具超时、结果大小、匹配数量和命令输出继续使用应用固定上限，模型不能提高或关闭限制。
- **N6（并发安全）：** 只读并发不得突破工作区边界或破坏结果隔离；具有副作用的操作不得并发执行，也不得越过前后安全屏障。
- **N7（取消可靠性）：** 取消后不得开始新的模型迭代、审批或工具调用；已经持久化的成功结果不得被误改为失败，尚未完成的状态不得被误标为成功。
- **N8（持久化一致性）：** 助手迭代、工具调用、工具结果、Token 用量、停止原因和会话模式应保持一致。程序中断后，不自动重试或恢复未完成的 Agent Loop，而是准确显示其中断状态。
- **N9（错误隔离）：** 单次模型流、工具、审批或持久化失败不得导致应用退出、损坏其他会话，或使已经完成的副作用再次执行。
- **N10（三协议统一）：** 供应商协议差异不得改变 Agent 的迭代计数、停止语义、工具可用范围、事件含义、结果排序或用户可见状态。
- **N11（兼容既有能力）：** 普通无工具对话、流式文本、extended thinking、会话管理、历史恢复、工作区边界、严格 UTF-8、结构化工具错误和 s02 审批流程继续工作。
- **N12（并发范围）：** 同一时间仍只处理一个用户发起的 Agent 回合；本阶段的并发仅用于同一工具批次内允许并行的连续只读调用。
- **N13（可测试性）：** 循环、事件顺序、双路收集、停止条件、批次屏障、Plan Mode 和三协议转换均可通过模拟模型流、临时工作区和本地存储验证，不依赖真实 API Key 或外部网络。
- **N14（数据安全）：** 事件、消息、日志和工具结果不得泄漏配置中的 API Key 或环境密钥；Plan Mode 不得通过未公开工具或替代路径产生写入和命令副作用。
- **N15（状态留痕）：** s03 的源码注释、项目导读和规划文档遵守现有状态标签规则；不得删除或改写 s01、s02 的历史说明。

## 不做的事

- 不新增权限策略系统、规则记忆、会话级自动批准、工具白名单、命令沙箱或权限配置。
- 不新增模型主动向用户提问、请求补充信息或请求确认的交互工具；仅保留 s02 已有的副作用工具 `Y/N` 批准。
- 不实现上下文压缩、自动摘要、消息淘汰或 Token 窗口管理；上下文超过供应商限制时按模型流错误停止。
- 不实现模型请求失败后的自动重试、供应商切换或断点续跑。
- 不在程序重启后自动恢复未完成的 Agent Loop，也不自动重试未完成的工具调用。
- 不在计划完成后自动执行；必须由用户输入 `/do`。
- 不实现命名计划、多个候选计划、计划版本管理、计划编辑器或计划差异比较；每个会话只认最近一次成功完成的计划。
- 不新增工具，也不改变 s02 六个工具的业务能力、参数格式、工作区范围、超时或结果上限。
- 不实现 MCP、插件工具、远程工具服务器、动态工具安装或模型自定义工具。
- 不实现多个用户任务、多个会话或多个 Agent Loop 的并行执行。
- 不允许任何副作用工具并发执行，也不允许 Plan Mode 执行写入或命令。
- 不实现二进制文件、多模态、Git 专用工具、文件删除、移动、复制或整文件覆盖等新能力。
- 不持久化并重放完整底层事件日志；只持久化恢复会话行为所需的消息、工具记录、用量、停止状态和 Plan Mode 数据。
- 不计算 Token 价格、任务成本或预算，也不发送遥测。
- 不将 20 轮上限、连续三轮未知工具阈值或工具可用策略开放给模型或配置文件修改。
- 不扩展 Windows 之外的平台支持。

## 验收标准

- **AC1（F1、F3、F14）：自主完成任务。** 使用模拟模型依次返回“读取工具调用 → 根据结果提出下一批工具 → 无工具最终回复”；发送一次用户消息后，MyCode 自动完成全部迭代和工具回写，不需要额外用户消息。
- **AC2（F2）：迭代消息独立。** 运行一个包含三次模型响应的任务；界面和重启后的历史中均存在三条顺序正确、状态准确的助手迭代消息，包括没有正文的纯工具调用消息。
- **AC3（F4、F5）：20 轮安全上限。** 模拟模型每轮都请求工具；MyCode 最多发起 20 次模型请求，第 20 次的新工具调用不执行，本回合以“达到迭代上限”结束，并保留此前结果。
- **AC4（F6）：取消模型流。** 在模型持续输出文本时取消；流立即中止，部分文本保留为取消状态，不启动工具或下一次模型迭代，随后仍可发送新任务。
- **AC5（F6、F20）：取消工具阶段。** 分别在等待审批和工具执行期间取消；待审批、未启动和可中断调用进入正确终态，已完成结果保留，不再继续循环。
- **AC6（F7）：未知工具保护。** 模型连续三轮只请求不同的未注册工具；前两轮错误正常回写，第三轮后停止且不发起第四轮。中间插入任一已注册工具调用后，连续计数清零。
- **AC7（F8）：模型流错误。** 分别模拟显式流错误和没有正常结束事件的意外中断；MyCode 保存已收到的部分内容和实际用量，将当前迭代与回合标为失败，不自动重试或执行不完整调用。
- **AC8（F9、F10）：双路事件收集。** 使用受控分片流逐步释放文本、思考内容和工具参数；消费者能在流尚未结束时收到实时事件，结束后又能得到完整文本、完整参数、结束原因和用量，没有重复或遗漏。
- **AC9（F9、F11）：进度与关联。** 执行包含多轮、多工具和审批的任务；事件消费者能观察回合开始、迭代编号与上限、工具等待与完成、审批等待以及最终停止原因，并通过稳定标识关联对应消息和调用。
- **AC10（F12）：顺序安全屏障。** 模拟“两个读取 → 一个写入 → 一个读取 → 一个命令”；前两个读取实际并发，写入只在它们都结束后启动，后一个读取只在写入结束后启动，命令最后审批并执行。
- **AC11（F13）：批次失败隔离。** 同一响应包含成功、参数无效、拒绝、超时和失败调用；其他合法调用仍完成，回写模型的结果数量完整且按原始调用顺序排列。
- **AC12（F15）：进入 Plan Mode。** 输入 `/plan` 后不请求模型，界面显示只读模式；随后发送任务时仍可进行多轮读取、查找和搜索，但模型收到的可用工具不包含写入或命令。
- **AC13（F16）：Plan Mode 越权保护。** 模拟模型在 Plan Mode 中直接返回已注册的写入或命令调用；调用不进入审批且不产生副作用，模型收到“当前模式不可用”结果，该轮不计为未知工具迭代。
- **AC14（F17）：执行最近计划。** 完成一个 Plan Mode 任务后输入 `/do`；MyCode 无需额外消息便切换为全工具模式，携带最近计划和会话上下文启动 Agent Loop，并可请求全部六个工具。
- **AC15（F17）：缺少计划。** 在没有成功完成计划的会话中输入 `/do`；MyCode 明确提示没有可执行计划，不请求模型，也不产生工具副作用。
- **AC16（F18）：模式和计划恢复。** 建立两个处于不同模式的会话并保存计划，切换会话及重启 MyCode；每个会话恢复自己的模式和最新计划，互不串用。
- **AC17（F19）：Token 用量。** 模拟三次迭代分别返回不同用量；每条助手消息保存自身数值，运行中的累计事件逐次增加，结束后的回合总量等于三次迭代之和，重启后仍可查看。
- **AC18（F20）：批准后自动续跑。** 模型请求写入和命令时，在批准前不产生副作用；批准或拒绝后无需用户再发消息，结果自动回写并继续下一次模型迭代。
- **AC19（F21）：三协议一致。** 对 Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions 运行等价的多轮模拟场景；三者产生相同语义的迭代、事件、工具结果、停止条件和 Plan Mode 行为。
- **AC20（回归）：普通对话与 s02 能力。** 运行现有无工具对话、流式文本、extended thinking、工具边界、审批、持久化、取消和会话测试；既有行为继续通过。
- **AC21（整体流程）：Plan 到执行端到端。** 用户输入 `/plan`，提交需要读取多个文件的任务，获得最终计划，再输入 `/do`，批准写入和测试命令；MyCode 自动循环到无工具最终回复，历史中可观察全部迭代、调用、结果、用量和最终完成状态。
