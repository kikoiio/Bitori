# MyCode 五层权限系统 Spec

## 背景

MyCode 在 s02–s04 已有：文件工具的真实路径边界（WorkspacePaths）、写/命令工具的
逐项 Y/N 审批（ApprovalCoordinator）、Plan/Do 模式过滤（ToolPolicy），且工具被拒后
Agent Loop 会继续运行。但审批没有记忆——每条 git 命令、每次文件写入都要问一遍；
没有规则配置——无法声明「git 命令一律放行」；没有危险命令兜底——用户一旦手滑批准
高危命令就直接执行；审批粒度也只有「本次批准/拒绝」两选。

## 目标

- 建立统一权限判定管线，工具执行前按固定顺序过五层：危险命令黑名单 → 路径沙箱 →
  可配置规则 → 权限档位 → 人在回路，判定结果只有放行/询问/拒绝三种。
- 黑名单用正则在执行前硬拦截已知高危命令，任何配置、档位、用户批准都无法放开。
- 文件操作限制在工作区内：先解析符号链接得到真实路径，再做前缀判断，防逃逸。
- 规则按「工具名(模式)」声明 allow/ask/deny，支持精确与 glob 匹配；用户级、项目级、
  本地级三个 YAML 合并判定，deny 压过 ask、ask 压过 allow，与写在哪层无关。
- 三档权限模式（严格/默认/放行）整体切换信任等级并持久化；deny 在任何档位生效。
- 规则未命中或命中 ask 时把决定权交回用户，支持本次、本会话、永久三种放行。
- 权限被拒（任何来源）不终止 Agent Loop，拒绝原因回写给模型，由模型调整策略。

## 功能需求

### 判定管线

- **F1：统一判定顺序。** 执行模式下每次工具调用在执行前按固定顺序判定：
  危险命令黑名单 → 路径沙箱 → 规则引擎 → 权限档位 → 人在回路。
  任何一层给出拒绝即终止判定、不执行；判定为询问才进入人在回路。
  Plan 模式的只读过滤保持不变，仍在管线之前生效（被 Plan 拦截的调用不进入管线）。
- **F2：判定结果三态。** 每次判定的结果只有放行、询问、拒绝三种：
  放行直接执行；询问进入人在回路；拒绝不执行并把原因写入工具结果。

### 危险命令黑名单

- **F3：黑名单硬拦截。** run_command 的命令文本在执行前与内置正则集匹配，
  命中即拒绝，不再进入后续层。黑名单内置于代码，任何 YAML 规则、权限档位、
  人在回路批准都无法放开。初始覆盖类别：递归强制删除、格式化与磁盘分区操作、
  关机重启、注册表高危写入、禁用系统安全组件、下载内容直接执行。
  黑名单只作用于 run_command；文件类工具由沙箱层兜底。

### 路径沙箱

- **F4：路径沙箱。** 文件类工具（read_file、write_file、edit_file、find_files、
  search_text）的路径参数先解析符号链接得到真实路径，再对工作区根做前缀判断；
  目标在工作区外即拒绝。run_command 不适用沙箱（其风险由黑名单、规则和
  人在回路约束）。既有 WorkspacePaths 能力并入管线作为统一拒绝来源。

### 可配置规则

- **F5：规则格式。** 规则写成「工具名(模式)」，如 run_command(git *)。
  工具名只接受六个实际工具名；run_command 的模式匹配完整命令文本，
  文件类工具的模式匹配工作区相对路径。支持精确匹配与 glob 通配。
  每条规则的结果为 allow、ask、deny 三选一。
- **F6：三层规则文件。** 规则分别存放在用户级（~/.mycode/permissions.yaml）、
  项目级（<工作区>/.mycode/permissions.yaml）、本地级
  （<工作区>/.mycode/permissions.local.yaml）三个 YAML 文件；
  读取时合并成一个规则集合，层级不参与优先级，只决定新规则写到哪里。
- **F7：优先级合并。** 合并集合中所有命中规则按 deny 压过 ask、ask 压过 allow
  取最终结果，与规则写在哪一层无关。
- **F8：只读可控。** 六类工具（含只读工具）都能被规则匹配，
  例如可用 deny read_file(**/.env) 保护密钥文件。

### 权限档位

- **F9：三档语义。**
  严格档：所有工具调用（含只读）都进入询问——allow 类规则（含会话、永久）
  不生效，deny 规则仍直接拒绝；
  默认档：只读工具未命中规则时自动放行，写/命令工具未命中规则时询问，
  命中规则按规则结果执行；
  放行档：全部调用自动放行，但黑名单、沙箱、显式 deny 规则仍然拦截。
- **F10：档位切换与持久化。** 通过斜杠命令在三档间切换；切换结果写入本地级
  配置，同一工作区下次启动时恢复（含放行档）；当前档位在界面状态区持续可见。

### 人在回路

- **F11：询问与三种放行。** 判定为询问时，界面展示工具名、参数摘要，
  用户可选：本次放行、本会话放行、永久放行、拒绝。
  本会话放行将规则记入会话内存（不写文件，会话结束消失）；
  永久放行将规则写入本地级 YAML。生成的规则一律精确匹配：
  命令类记录完整命令文本，文件类记录完整相对路径。
- **F12：会话规则同等合并。** 会话内生成的规则与三层 YAML 规则进入同一个
  合并集合，按同一优先级（deny>ask>allow）参与判定。

### 拒绝反馈

- **F13：拒绝不终止 Agent Loop。** 任何来源的拒绝（黑名单、沙箱、deny 规则、
  用户在人回中拒绝）都不终止 Agent Loop；工具结果携带拒绝来源与原因
  回写给模型，模型可据此调整策略继续执行。

## 非功能需求

- **N1（平台兼容）：** 继续支持 Windows 10/11、Windows Terminal、PowerShell
  和项目规定的 Node.js 运行环境，不新增其他平台承诺。
- **N2（向后兼容）：** s01–s04 既有能力不回归：Agent Loop、Plan/Do 切换、
  三协议流式输出、系统提示与缓存、持久化与恢复、取消行为。
  在「默认档 + 无任何规则文件」的出厂状态下，工具行为与 s04 一致：
  只读自动放行，写/命令逐条询问。
- **N3（安全默认）：** 规则文件全部缺失时视为空规则集，不因缺文件放开任何操作；
  档位配置缺失时回到默认档。
- **N4（配置显错）：** 规则文件存在但解析失败（YAML 语法错误、结构非法、
  工具名未知、结果值非法）时不静默忽略——启动报错并指明是哪个文件、什么问题，
  避免用户以为 deny 保护已生效而实际未加载。
- **N5（确定性）：** 相同工具调用、相同规则集合、相同档位下，判定结果完全一致；
  判定顺序与优先级合并不依赖文件读取顺序。
- **N6（可测试性）：** 权限引擎不依赖 TUI、网络或真实模型；黑名单、沙箱、
  规则解析与合并、三档语义、优先级、人在回路三选择的规则生成均可通过
  单元测试与模拟调用验证。
- **N7（界面解耦）：** 权限引擎不读取或修改 TUI 状态；询问请求与判定结果
  通过现有审批/事件通道发布，界面只消费。
- **N8（判定开销）：** 每次工具调用的判定（正则 + glob + 规则合并）在毫秒级
  完成，不引入可感知延迟；规则文件在会话启动时加载，运行中写入的永久规则
  当前会话内立即生效。
- **N9（敏感数据）：** 规则文件、日志与界面展示不包含 API Key、令牌等密钥材料。
- **N10（状态留痕）：** s05 源码注释以 [s05] 标签开头；被替换的 s01–s04 实现
  按规则就近保留块注释并写明替换关系；Project_Guide 新增 s05.md。

## 不做的事

- 不做网络请求限制、资源配额（CPU/内存/磁盘用量）、审计日志，留给后续章节。
- 不解析 PowerShell 命令语义（不做 AST 解析、变量展开、管道分解）；
  黑名单与规则匹配基于命令文本字面，刻意混淆过的命令不在本步防御范围。
- run_command 不纳入文件系统沙箱；命令的工作区外风险由黑名单、规则、
  档位与人在回路约束，不做系统调用级拦截。
- 不改变六个工具的业务能力、参数格式、超时与结果上限；Plan/Do 语义不变。
- 不支持 Claude Code 风格工具别名（Bash、Read 等），规则只认实际工具名。
- 人在回路只生成 allow 类规则；「拒绝」只当次生效，不提供从界面生成
  永久 deny 规则的入口（deny 规则需手写 YAML）。
- 放行粒度不提供选择：一律精确匹配（完整命令文本 / 完整相对路径）；
  需要前缀或整目录放行时，由用户手写 YAML glob 规则。
- 「本会话放行」不持久化、不随会话恢复；除档位外不新增会话级存储结构。
- 不提供规则文件热重载：会话运行中外部手动编辑 YAML 需重启生效；
  通过人在回路写入的永久规则当前会话内立即生效。
- 不提供规则的界面编辑器；手写 YAML 与人在回路生成是仅有的两个规则来源。
- 询问不提供超时自动决定：用户做出选择前调用一直挂起，现有取消行为不变。
- 不新增权限相关的模型可见工具或系统提示模块；权限判定对模型只通过
  工具结果中的拒绝原因呈现。

## 验收标准

- **AC1（F1、F2）：判定顺序。** 构造组合场景：黑名单命中的命令在放行档 +
  命中 allow 规则时仍被拒绝；沙箱逃逸路径在命中 allow 规则时仍被拒绝。
  前层拒绝后不再进入后续层，判定结果只有放行/询问/拒绝三态。
- **AC2（F3）：黑名单硬拦截。** 六个类别各取代表性命令（递归强制删除、
  格式化/分区、关机重启、注册表高危写入、禁用安全组件、下载执行），
  在放行档、用户级 allow 规则、人在回路批准三种尝试下全部仍被拒绝，
  拒绝原因标注黑名单。
- **AC3（F4）：沙箱防逃逸。** 工作区内创建一个指向工作区外目标的符号链接，
  对其读、写均被拒绝（含放行档）；工作区内正常路径的文件操作不受影响。
- **AC4（F5、N4）：规则解析。** 精确规则匹配完整命令文本；glob 规则匹配
  命令前缀与相对路径；含未知工具名或非法结果值的规则文件在启动时报错，
  错误信息指明文件与问题。
- **AC5（F6、N3）：三层合并与缺省。** 三层文件同时存在时合并为一个集合；
  删除全部规则文件后启动正常，行为等同默认档 + 空规则集。
- **AC6（F7）：优先级与层级无关。** 同一调用分别在用户级命中 allow、
  项目级命中 ask、本地级命中 deny 时结果为 deny；只命中 allow 与 ask 时
  结果为 ask；调换规则所在层级结果不变。
- **AC7（F8）：只读可控。** 配置 deny read_file(**/.env) 后，模型读取
  工作区内 .env 被拒绝，读取其他文件不受影响。
- **AC8（F9）：三档语义。** 严格档：只读调用也进入询问，命中 allow 规则的
  调用仍询问，命中 deny 规则的直接拒绝；默认档：只读未命中自动放行，
  写/命令未命中询问；放行档：写/命令未命中直接执行，命中 deny 仍拒绝。
- **AC9（F10）：档位切换与持久化。** 斜杠命令切换三档立即生效，切换写入
  本地级配置；重启同一工作区后恢复上次档位（含放行档）；界面状态区
  全程可见当前档位。
- **AC10（F11）：人在回路三选择。** 询问界面提供本次/本会话/永久/拒绝四选项。
  选本次：下次相同调用仍询问；选本会话：同会话相同调用不再询问，
  重启后失效；选永久：本地级 YAML 新增一条精确规则，当前会话立即生效。
- **AC11（F12）：会话规则同等合并。** 本会话放行的命令，与 YAML 中
  覆盖同一调用的 deny 规则冲突时，deny 胜出。
- **AC12（F13）：拒绝不终止。** 模拟模型流中先触发黑名单拒绝、再触发
  用户拒绝，Agent Loop 均不终止；模型收到的工具结果包含拒绝来源与原因，
  迭代继续。
- **AC13（N2）：回归。** `npm run check` 全部通过
  （typecheck、lint、既有测试套件、构建）。
- **AC14（人工端到端）：真实会话走查。** 配置一条 allow run_command(git *)
  规则、默认档启动真实会话：git status 不询问直接执行；npm test 询问一次，
  选本会话后再次执行不再询问；切换放行档后写文件不再询问；
  执行黑名单命令仍被拒绝；重启后本会话放行的 npm test 恢复询问。
