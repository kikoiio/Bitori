# MyCode Spec

## 背景

MyCode 是一个仅支持 Windows 的命令行 AI 对话助手。用户从终端运行 `MyCode` 后进入全屏交互界面，与配置好的大模型进行连续对话。

当前阶段要建立最小但完整的对话能力：支持 Anthropic Claude、OpenAI Responses 和 OpenAI Chat Completions 三种协议后端；模型回复在生成过程中持续显示；Claude 可启用 extended thinking；同一会话中的历史消息会随后续请求一并提供给模型；会话持久保存，重新启动后自动恢复最近一次会话。

## 目标

- 用户可以通过一次命令进入稳定可用的全屏对话界面。
- 用户可以在同一份 YAML 中维护多个模型配置，并在启动时选择使用的配置。
- 不同供应商在界面中呈现一致的发送、流式输出、取消、错误和用量行为。
- 对话与思考内容能够持久保存，退出程序不会丢失会话。
- Provider 边界清晰，未来增加其他协议时无需改动对话界面的核心行为。

## 功能需求

- F1：用户运行 `MyCode` 后进入仅支持 Windows 的全屏 TUI，界面至少包含消息区、输入区和状态区。
- F2：程序固定读取 `%USERPROFILE%\.mycode\config.yaml` 和同目录下的 `.env`，不从其他位置搜索配置。
- F3：一份 YAML 可以包含多个配置。每项配置包含：
  - `name`：唯一配置名称。
  - `protocol`：`anthropic`、`openai-responses` 或 `openai-chat`。
  - `model`：模型标识。
  - `base_url`：API 请求地址。
  - `api_key`：`.env` 变量引用，例如 `${OPENAI_API_KEY}`。
  - `thinking`：扩展思考配置，可选，默认关闭。可使用布尔值；`true` 表示自动兼容 adaptive 与 manual thinking。也可使用对象显式指定 `adaptive`，或指定 `manual` 及其 `budget_tokens`、`max_tokens`。
- F4：用户可通过 `MyCode --profile <name>` 选择配置。未指定时，只有一个配置则直接使用；存在多个配置则显示配置选择界面。
- F5：配置文件、`.env`、必填字段或所引用的密钥缺失，以及配置名称重复或指定配置不存在时，程序显示明确错误且不发起模型请求。错误信息不得显示 API Key。
- F6：每个会话关联一个配置。选择配置后，程序自动恢复该配置最近使用的会话；不存在历史会话时创建新会话。
- F7：用户可以在界面中新建会话、查看历史会话列表并切换会话。
- F8：用户发送消息后，模型完整返回前，消息区就持续追加新内容，不等待全部生成完成。
- F9：Anthropic Claude、OpenAI Responses 与 OpenAI Chat Completions 后端具有一致的发送、流式显示、取消、完成和错误提示行为。
- F10：启用 Claude extended thinking 时，思考内容在生成期间展开；完成后自动折叠；用户可以手动展开或折叠。`thinking: true` 时先请求 adaptive thinking；仅在供应商明确返回不支持 adaptive 的参数错误时，使用 `budget_tokens: 4096`、`max_tokens: 8192` 的 manual thinking 重试。其他错误不触发自动重试。
- F11：同一会话的历史消息会随下一次请求提供给模型，使模型能够理解此前对话。
- F12：会话、消息、思考内容、完成状态和 token 用量持久保存到本地 SQLite；退出并重新启动后仍可恢复。
- F13：恢复历史会话时，普通消息、已取消回复和思考内容均可查看；已完成的思考内容默认折叠。
- F14：生成期间按 `Ctrl+C` 取消当前请求，保留并标记已输出内容，同时留在对话界面。保留的部分回复属于后续对话历史。
- F15：程序空闲时按 `Ctrl+C` 安全退出，并确保已完成或已取消的对话内容已经保存。
- F16：网络错误、认证失败、限流或供应商错误会显示为可理解的信息，且不会破坏已有会话；用户可以继续操作。
- F17：状态区显示当前配置名称、模型和请求状态；供应商提供 token 用量时，显示本次请求的输入、输出 token 数量。
- F18：不同供应商的原始事件由统一 Provider 边界转换，界面和会话功能不依赖具体供应商的事件格式。

## 非功能需求

- N1（平台兼容）：首个版本支持 Windows 10/11，并以 Windows Terminal 中的 PowerShell 为主要运行环境。
- N2（运行环境）：使用受支持的 Node.js LTS 版本运行，源代码使用 TypeScript，并提供可重复执行的构建、测试和启动命令。
- N3（流式响应）：收到供应商的流式事件后应立即更新界面；网络请求和 SQLite 操作不得阻塞键盘输入或界面刷新。
- N4（界面稳定）：终端窗口缩放时自动调整布局，不崩溃、不残留错位内容；窗口过小时显示明确提示。
- N5（字符支持）：输入、显示和持久化均完整支持 Unicode，包括中文、代码块和常见终端字符。
- N6（密钥安全）：API Key 不得写入 YAML、SQLite、日志或用户可见错误信息；`.env` 不得被会话数据复制或导出。
- N7（本地隐私）：除调用用户选择的模型 API 外，不向其他服务发送配置、会话或使用数据；本阶段不加入遥测。
- N8（持久化可靠性）：每条已完成、已取消或失败的消息状态应一致保存；程序异常退出后，已提交的数据仍可读取，数据库不得因单次中断而整体不可用。
- N9（错误隔离）：单次 API 请求、单条流事件或单个会话发生错误时，不得导致其他历史会话丢失或整个程序无条件退出。
- N10（可扩展性）：新增供应商协议时，现有 TUI、会话存储和核心对话流程无需针对新供应商重写。
- N11（可测试性）：Provider、配置、会话存储和对话状态可以使用模拟数据独立测试，不依赖真实 API Key；真实 API 仅用于明确的端到端验收。
- N12（退出清理）：正常退出或取消请求时，应关闭网络流、恢复终端状态并释放 SQLite 连接，不在终端中留下失效的全屏界面。

## 不做的事情

- 不实现 tool use、function calling、MCP 或任何 Agent 工具系统。
- 不读取项目文件，不建立代码库上下文，不搜索、创建、修改或删除用户文件。
- 不执行 Shell、PowerShell、Git、测试或其他外部命令。
- 不实现代码补全、补丁生成、自动编辑或 IDE 集成。
- 不支持图片、音频、附件或其他多模态输入。
- 不支持 Windows 之外的操作系统，也不承诺兼容旧式终端或第三方终端模拟器。
- 不在 TUI 内编辑供应商配置或 API Key；配置由用户在 YAML 和 `.env` 中维护。
- 不在同一会话中途切换 Provider 配置；需要使用另一配置时创建或切换到对应会话。
- 不同时执行多个模型请求。
- 不实现云端同步、用户账号、远程会话共享或跨设备恢复。
- 不实现会话导入、导出、重命名或删除；本阶段只提供新建、查看列表和切换。
- 不实现自动对话摘要、长期记忆提取或超出模型上下文窗口后的自动压缩；超过供应商限制时显示错误。
- 不提供 token 成本换算、预算管理或账单统计。
- 不保证完整 Markdown 排版或代码语法高亮；必须正确保留和显示模型返回的文本内容。
- 不发布到 npm，也不制作 Windows 安装程序；本阶段只保证从项目源码构建并运行。

## 验收标准

- AC1（F1）：在 Windows Terminal 的 PowerShell 中运行 `MyCode`，程序进入全屏界面，并可看到消息区、输入区和状态区。
- AC2（F2、F3）：在固定目录放置包含多个配置的 `config.yaml` 和 `.env` 后，MyCode 能读取六个配置字段，并将 `${变量名}` 解析为 `.env` 中的密钥。
- AC3（F4）：配置文件只有一个配置时直接进入对话；存在多个配置时显示选择界面；使用 `--profile <name>` 时直接选中对应配置。
- AC4（F5）：分别制造配置文件缺失、`.env` 缺失、字段缺失、变量不存在、名称重复和未知 profile，程序均阻止 API 请求并显示不含密钥的明确错误。
- AC5（F6）：为两个配置分别创建会话并重新启动；选择其中一个配置后，只自动恢复与该配置关联的最近会话。
- AC6（F7）：用户可以在 TUI 中新建会话、打开历史会话列表并切换到任一已有会话，消息内容随切换正确变化。
- AC7（F8、F9）：分别使用有效的 Anthropic、OpenAI Responses 和 OpenAI Chat Completions 配置请求一段较长回复；三者均在请求结束前多次更新消息区，并最终显示完整回答。
- AC8（F10）：分别以支持 adaptive 和仅支持 manual thinking 的 Claude 模型使用 `thinking: true` 发起请求；前者直接成功，后者在明确的不兼容错误后以 `budget_tokens: 4096`、`max_tokens: 8192` 自动重试。两者的思考内容生成时可见，完成后自动折叠，并可由用户重新展开和折叠。认证、限流和网络错误均不得触发该重试。
- AC9（F11）：用户先提供一个特定事实，再在下一轮只询问该事实；模型能够依据前一轮内容回答，证明当前会话历史已随请求发送。
- AC10（F12、F13）：完成包含普通回复、思考内容和已取消回复的会话后退出并重启；数据库中的内容、状态和可用 token 统计均恢复，已完成思考默认折叠。
- AC11（F14）：模型生成期间按 `Ctrl+C`，网络流停止、部分回复被保留并标记为已取消，界面仍可继续发送下一条消息。
- AC12（F15）：程序空闲时按 `Ctrl+C`，全屏界面关闭并恢复正常终端；再次启动后退出前的已提交消息仍然存在。
- AC13（F16）：分别模拟认证失败、限流、网络中断和供应商错误；界面显示可理解的错误，历史消息不丢失，并允许继续操作或重新发送新消息。
- AC14（F17）：状态区始终显示当前配置、模型和请求状态；供应商返回用量数据后显示输入、输出 token 数量。
- AC15（F18）：使用不依赖 Anthropic 或 OpenAI SDK 事件格式的模拟 Provider 驱动完整对话，TUI、取消逻辑和会话保存均能正常工作。
- AC16（N3、N4、N5）：流式生成时键盘与界面保持响应；调整终端尺寸不会崩溃；输入并恢复包含中文、换行和代码块的消息时内容不损坏。
- AC17（N6、N7）：检查 YAML、SQLite、日志和错误输出，均找不到 `.env` 中的真实 API Key；除选定模型 API 外没有其他网络请求。
- AC18（N8、N9）：保存若干消息后强制终止程序并重新启动，已提交消息仍可读取；一次失败请求不会损坏其他会话。
- AC19（N10、N11）：配置、Provider、会话存储和对话状态测试可在没有真实 API Key、没有外部网络的环境中运行并通过。
- AC20（N12）：完成、取消、请求失败和正常退出四种路径都能关闭活动请求与数据库连接，并正确恢复终端显示。
