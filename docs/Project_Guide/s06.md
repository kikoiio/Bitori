# s06：MCP 工具客户端

> 本文是 s06 完成时点的实现快照，后续阶段可能已替换或扩展其中实现；当前架构以最新阶段文档与源码为准。

## 状态概览

s06 把外部 MCP Server 的工具接入 Bitori 既有工具中心。启动时读取用户级和项目级 `mcp_servers`，并发连接各 Server，完成初始化握手、工具发现和注册；模型看到的是普通工具，Agent Loop、权限审批、执行结果与持久化链路无需 MCP 分支。

## 协议与传输

- 协议固定为 `2025-06-18`，执行 `initialize` → `notifications/initialized` → `tools/list`；调用走 `tools/call`。
- stdio 启动本地子进程并使用换行分隔 JSON-RPC；Streamable HTTP 每条消息 POST，支持 JSON 或 SSE 响应、session id 与协议版本 header。
- `JsonRpcPeer` 以递增 id 和 pending map 配对异步响应，覆盖乱序、错误、超时、取消和连接关闭。

## 工具与安全

工具公开名为 `mcp__<server>__<tool>`，保留远端 description 与 inputSchema。远端结果转换为统一 `ToolExecutionResult`。所有 MCP 工具默认视为有副作用，不信任远端 annotation 自动放行，因此继续经过 Plan 过滤、s05 权限档位和人在回路。MCP 工具也能生成会话或永久 allow 规则。

## 配置与隔离

用户级 `%USERPROFILE%/.bitori/config.yaml` 先加载，项目级 `<workspace>/.bitori/config.yaml` 后覆盖同名 Server。stdio 的 command/args/env 和 HTTP 的 url/headers 支持 `${VAR}`。每个 Server 拥有独立缓存 Client；单项连接、协议或名称冲突失败只告警自身，其他 Server 正常注册。应用关闭时统一释放全部连接。

## 范围边界

本步不实现 MCP resources、prompts、sampling、健康检查、自动重连、OAuth、工具列表热更新或旧 HTTP+SSE 兼容。

## 验证

新增测试覆盖配置合并/展开、JSON-RPC 乱序配对、HTTP JSON/SSE 与 header、完整客户端生命周期、分页列举和多 Server 故障隔离。Linux 容器可完成 typecheck、lint、build 与专项测试；Windows/PowerShell 相关既有测试及真实 Server 走查仍按 checklist 在目标环境执行。
