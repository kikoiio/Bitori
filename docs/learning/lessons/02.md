# 第 02 课：统一工具系统

- 前置：第 01 课。
- 结果：模型能请求六个内置工具，Bitori 统一审批、执行、结构化返回结果并回灌给模型。
- 预计：8-10 小时。
- 环境：同第 01 课；命令工具人工验收需要 PowerShell。

## 1. 为什么学这一课

聊天客户端只把模型输出显示给人。工具系统让模型读取和修改真实工作区，因此必须同时解决协议一致性、路径安全、审批、超时、截断和持久化。本课把这些横切问题做成一条统一管线。

## 2. 能力规格

- 六个工具：read_file、write_file、edit_file、run_command、find_files、search_text。
- 三协议输出统一的工具调用事件；参数分片在完整后组装。
- 只读工具自动执行；写文件、编辑和命令逐项显示参数并等待 Y/N。
- 文件工具限制在启动工作区内，拒绝绝对路径、穿越和链接逃逸，只处理 UTF-8 文本。
- 所有工具有超时、结果大小和匹配数上限；错误结构化，单项失败不影响同批其他项。
- 首批工具全部得到终态后一次性回灌模型；拒绝也作为结果返回。
- 工具调用与结果写入 SQLite；重启后未终态调用标记 interrupted，不自动重试。

## 3. 代码走读

1. `src/tools/types.ts`、`src/tools/limits.ts`：契约先于实现。
2. `src/tools/workspace-paths.ts`、`src/tools/utf8.ts`：安全与文本边界。
3. `src/tools/implementations/`：六个工具的行为与错误码。
4. `src/tools/registry.ts`、`src/tools/call-assembler.ts`：注册与流式参数组装。
5. `src/tools/approval-coordinator.ts`、`src/tools/batch-coordinator.ts`：审批与批次调度。
6. `src/tools/executor.ts`、`src/tools/create-tool-system.ts`：组合根。
7. Providers：协议工具定义与调用事件转换。
8. `src/chat/controller.ts`、存储迁移与 TUI 工具卡片。

## 4. 实现任务

1. 定义 Tool 契约与限制。检查项为非法参数、超时、截断均有结构化错误。
2. 实现 WorkspacePaths。检查项为穿越、绝对路径、不存在、目录和链接逃逸测试通过。
3. 实现六个工具。检查项为每个工具的成功、失败、拒绝、截断行为均有测试。
4. 实现注册、组装与执行。检查项为未知工具、参数分片和批次隔离测试通过。
5. 接入三协议与控制器。检查项为模拟流能完成调用、执行、回灌、最终回复。
6. 接入审批与持久化。检查项为批准、拒绝、重启中断恢复测试通过。
7. 更新 TUI 工具卡片与 README。检查项为参数、状态、风险和结果可见。

## 5. 检查点

### 自动验证

```powershell
npm run check
node dist/bin/bitori.js --help
```

### 人工验收

在临时工作区让模型完成读取、创建、编辑、查找、搜索和命令任务；分别验证批准、拒绝、超时和命令风险提示。结果记录到本课 `checklist.md`。

## 6. 常见卡点

- 把路径校验写在工具里：路径解析必须集中在 WorkspacePaths，工具只消费结果。
- 结果太大拖垮 TUI：所有输出在 executor 边界统一截断，并报告原始规模。
- PowerShell 输出乱码：启动时设置 UTF-8，再验证 Unicode stdout/stderr。
- 审批与执行竞争：写入和命令串行；连续只读才并发。

## 7. 延伸与边界

本课控制器只执行首批工具并做一次回灌，还不是自主 Agent。模型不能根据执行结果继续发起下一批；这个循环在第 03 课实现。
