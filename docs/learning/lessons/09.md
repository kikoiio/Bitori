# 第 09 课：Slash Command 命令框架

- 前置：第 08 课。
- 结果：Bitori 拥有统一命令注册表，支持内置命令、别名、补全、用户 Markdown prompt 命令与使用统计。
- 预计：5-7 小时。
- 环境：无外部依赖。

## 1. 为什么学这一课

Slash command 是终端 Agent 的操作面板。若每加一个命令都在 TUI 里写一个 `if`，很快会失控。命令需要统一类型、统一注册、统一解析，并允许用户用 Markdown 扩展。

## 2. 能力规格

- `parseCommand` 把输入拆成命令名与参数；非 `/` 开头返回 null。
- `CommandRegistry` 支持注册、别名、冲突检测、前缀补全、排序列表。
- 内置 `help/h/?`、`plan`、`do`、`compact/c`。
- 用户命令从 `~/.bitori/commands` 与 `.bitori/commands` 加载；子目录成为命名空间，如 `review/security`。
- Markdown frontmatter 支持 `description` 与 `argument-hint`；正文中的 `$ARGUMENTS` 被参数替换，无占位时参数追加到末尾。
- 使用统计写入 JSON，按衰减分数和最近使用排序。
- 命令执行永远不直接进入 LLM；`prompt` 类型只生成要发送的文本。

## 3. 代码走读

1. `src/commands/registry.ts`：Command、Registry、parse 与内置命令。
2. `src/commands/loader.ts`：两层目录扫描、frontmatter、命名空间与参数渲染。
3. `src/commands/usage-tracker.ts`：JSON 持久化、衰减分数、最近使用。
4. `src/chat/commands.ts`：现有会话命令入口，后续迁移到统一 Registry。

## 4. 实现任务

1. 实现 Registry 与解析。检查项为别名、冲突、补全测试通过。
2. 实现 Markdown 加载。检查项为 frontmatter、命名空间、`$ARGUMENTS` 测试通过。
3. 实现使用统计。检查项为持久化与最近使用测试通过。
4. 接入 TUI。检查项为 `/` 前缀显示候选并可用 Tab/Enter 选择。

## 6. 常见坑

- 别名也必须参与冲突检测，否则 `find` 会路由到错误命令。
- 用户命令不能覆盖内置命令；加载时遇冲突跳过。
- 使用统计写失败不应导致命令失败。

## 实现快照与设计决策

> 以下为本课（s09）完成时点的实现快照；后续课次可能已替换或扩展对应实现。

### 阶段结果

把散落在控制器的 slash 分支抽象成统一 Registry，并让用户能用 Markdown 扩展 prompt 命令。

### 设计

- `src/commands/registry.ts` 定义 `Command` 与 `CommandRegistry`，内置 help/plan/do/compact。
- `src/commands/loader.ts` 扫描用户级与项目级 commands 目录，frontmatter 解析，子目录命名空间，`$ARGUMENTS` 替换。
- `src/commands/usage-tracker.ts` 记录次数与时间，JSON 持久化，按衰减分数排序。
- 现有 `src/chat/commands.ts` 保持会话命令兼容；后续 TUI 接入时逐步改为 Registry 分发。
