# 第 14 课：Agent Teams

- 前置：第 13 课。
- 结果：Bitori 具备长期团队模型、按成员持久化的文件邮箱、团队配置目录与成员进度状态。
- 预计：8-10 小时。
- 环境：无外部依赖；tmux/iTerm2 后端检测在对应终端人工验收。

## 1. 为什么学这一课

SubAgent 是星型调度，所有信息都要经过主 Agent。团队模式让成员拥有长期身份、邮箱和共享任务，可以把并行协作从“主 Agent 转述”变成“成员直接通信”。

## 2. 能力规格

- Team 记录名称、描述、lead、状态与成员花名册。
- 成员记录 name、role、status、worktreePath。
- 团队配置按名称持久化为目录内 `team.json`。
- 邮箱按成员一个 JSONL 文件，一条消息含 from、text、timestamp。
- 读取游标独立持久化；新实例能继续消费未读消息。
- 文件锁使用 `wx` 创建、过期清理、抖动重试；坏行跳过。
- `unreadCount`、`markAllRead`、`poll` 支持成员空闲轮询。
- 删除团队时若有 running 成员默认拒绝，force 才可删。
- 进度状态记录工具调用次数、token 数、最近 5 条活动描述。
- 本阶段不做跨机器分布式团队与实时流式通信。

## 3. 代码走读

1. `src/teams/file-mailbox.ts`：文件锁、JSONL 邮箱、游标恢复。
2. `src/teams/team.ts`：团队生命周期、成员花名册、持久化。
3. `src/teams/progress.ts`：成员活动进度与终端摘要。

## 4. 实现任务

1. 实现文件锁。检查项为互斥、过期锁清理。
2. 实现邮箱。检查项为发送、增量读取、坏行跳过、游标恢复。
3. 实现团队管理。检查项为创建、列表、成员更新、运行中保护、删除。
4. 实现进度。检查项为最近 5 条活动与命令截断描述。

## 5. 验证

```powershell
npm run typecheck
npm test -- tests/unit/teams/teams.test.ts
```

## 6. 常见坑

- 邮箱游标必须持久化，否则重启后旧消息会重复消费。
- 文件锁不能用普通写入后判断存在，必须用原子 `wx` open。
- 删除团队前必须检查 running 成员，避免杀掉仍在写邮箱的进程。
