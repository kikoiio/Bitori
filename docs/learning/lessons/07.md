# 第 07 课：上下文管理

- 前置：第 06 课。
- 结果：Bitori 在长会话中自动控制工具结果体积，并在接近上下文窗口时用结构化摘要压缩历史；用户可随时执行 `/compact`。
- 预计：8-10 小时。
- 环境：无需真实模型即可完成单测；自动压缩与手动压缩建议用一个低成本模型做一次人工验收。

## 1. 为什么学这一课

Agent 连续工作后，真正吃掉上下文的往往不是用户输入，而是 ReadFile、RunCommand、SearchText 的结果。若把大结果逐轮原样回放，请求会单调膨胀，最终被供应商以 context limit 拒绝。

本课把上下文管理拆成两层：轻量预防与全量兜底。第一层在请求组装前处理工具结果；第二层在接近窗口上限时用模型生成结构化摘要。

## 2. 能力规格

- 单条工具结果超过 50,000 字节时完整写入 `.bitori/tool-results/<callId>`，请求里只保留稳定预览体。
- 单轮聚合结果超过 200,000 字节时，从大到小依次落盘，直到回落阈值。
- 替换决策一旦写入就冻结；同一调用此后的预览逐字节一致，保护 prompt cache。
- 旧轮次中小结果使用 `[Stale output snipped: N bytes]` 占位，不额外写磁盘。
- token 估算以最近一次 provider usage 为锚点，新增内容按 3.5 字符/token 估算。
- 自动摘要阈值 `contextWindow - 13000`，手动 `/compact` 不受阈值限制。
- 摘要 Prompt 禁止工具调用，要求 `<analysis>` 草稿加 `<summary>` 正式摘要，正式摘要包含 9 个固定小节。
- 摘要后保留近期原文，条数至少 5 条；再追加最近文件、当前工具和边界提示三段恢复信息。
- 自动摘要连续失败 3 次熔断；手动压缩绕过熔断。
- `context_window` 可按 profile 配置；缺省 anthropic 为 200,000，openai 系为 128,000。

## 3. 代码走读

1. `src/toolresult/state.ts`：替换决策账本，seen 与 replacement 分开保存。
2. `src/toolresult/budget.ts`：单条落盘、聚合落盘、稳定预览体、旧轮次占位。
3. `src/compact/compact.ts`：token 锚点估算、近期原文边界、摘要请求与熔断。
4. `src/compact/recovery.ts`：最近文件快照、工具列表与边界提示。
5. `src/agent/runner.ts`：每次流式请求前执行两层管理，工具结果预算只影响请求，不改持久化历史。
6. `src/chat/commands.ts`、`src/chat/agent-controller.ts`：`/compact` 与 `/c` 命令路由。
7. `src/config/schema.ts`、`src/config/types.ts`、`src/config/loader.ts`：`context_window` 配置与协议默认值。

## 4. 实现任务

1. 实现替换账本。检查项为决策冻结与幂等测试通过。
2. 实现工具结果预算。检查项为单条、聚合、落盘失败降级测试通过。
3. 实现全量摘要。检查项为阈值、强制压缩、失败熔断测试通过。
4. 实现恢复状态。检查项为最近 5 个文件、工具清单与边界提示测试通过。
5. 接入 AgentRunner。检查项为请求前预算生效且持久化历史不被改写。
6. 接入命令与配置。检查项为 `/compact` 不触发普通对话、未知命令不发给模型。

## 5. 验证

```powershell

```

人工验收：让 Agent 读取一个大于 50KB 的文件，确认生成 `.bitori/tool-results/<callId>`；调低 `context_window` 后执行长任务，观察自动摘要；空闲时输入 `/compact` 确认显示压缩前后估算值。

## 6. 常见坑

- 预览体不能包含时间戳或随机数，否则每轮请求都会破坏缓存。
- 工具结果预算只能改请求副本，不能改 SQLite 中的原始调用记录，否则审计信息丢失。
- usage 锚点是替换而不是累加，否则估算值会越滚越大。
- 自动摘要请求必须显式禁止工具，否则摘要模型可能又开始调用工具。
