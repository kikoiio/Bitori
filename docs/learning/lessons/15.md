# 第 15 课：可观察性系统

- 前置：第 03 课（Agent Loop）、第 07 课（上下文管理）、第 10 课（Skill）。
- 结果：Bitori 具备结构化日志层、每会话请求级 JSONL trace（含重试与压缩事实）、上下文组成分析、技能/命令使用统计、CLI 观察命令与 TUI 调试面板。
- 预计：8-10 小时。
- 环境：无外部依赖；真实模型走查需要可用 profile。

## 1. 为什么学这一课

前 14 课构建的 harness 有一个共同盲区：出问题时无法回答"模型当时看到了什么、返回了什么、为什么停"。dsh 把 "Model-visible means logged. Every model request must be reconstructable from the log" 作为架构铁律，pi 用 `/session` 一条命令暴露全部运行事实。本课为 Bitori 补上同一层能力：观察不改变被观察者的行为，但让每一次模型交互都可回放。

## 2. 能力规格

- 结构化日志：`debug|info|warn|error` 四级，JSONL 按天滚动到 `~/.bitori/logs/`，默认保留 7 天；TUI 下唯一出口是文件，绝不写 stdout。
- 请求级 trace：每个会话一个 `~/.bitori/traces/<sessionId>.jsonl`，记录完整请求载荷、响应、工具调用、重试退避、压缩触发与领域事实；工具定义按内容摘要去重，只在变化时全量记录。
- 上下文组成：每轮把请求分解为固定桶（系统提示/环境/自定义指令/技能目录/长期记忆/工具定义/用户消息/助手消息/工具结果/提醒/压缩摘要），估算值与 provider 真实 input tokens 及差值一并入流。
- 使用统计：`load_skill` 成功、slash command 执行各记一行 JSONL 到 `~/.bitori/usage/skills.jsonl`，字段对齐 skill-tracker 超集（ts/kind/name/source/sessionId/profileName/cwd/agent/event_id）。
- CLI 观察命令：`trace show/tail/export/replay`、`usage stats/tail`、`sessions list/show`；export 默认脱敏、`--raw` 关闭。
- TUI 调试面板：`Ctrl+T` 切换，显示实时事件摘要、迭代/阶段、本轮与累计用量、已激活技能。
- 脱敏：API key 与 `.env` 值经全局 Redactor 在日志与 trace 落盘前替换为 `<redacted>`。
- 保留期：trace 默认保留 30 天（`trace.retention_days` 可配），日志 7 天（`logging.retention_days` 可配），启动时清理。

## 3. 代码走读

1. `src/shared/logger.ts`：全局 LogSink，串行异步追加链，失败只丢弃计数。
2. `src/shared/redact.ts`：`createRedactor` 精确串替换（长度 ≥ 8），长密钥优先；全局默认实例由组合根注入。
3. `src/shared/token-estimate.ts`：从 compact 提取的估算器（3.5 字符/token + usage 锚点），compact 以 re-export 保持兼容。
4. `src/agent/types.ts` + `src/agent/runner.ts`：新增 `request_prepared`/`request_retry`/`context_compacted` 三类 AgentEvent；重试基础退避可注入（`limits.retryBaseDelayMs`）。
5. `src/trace/writer.ts`：有界队列（256）串行追加，队列满丢弃并告警；写失败降级。
6. `src/trace/composition.ts`：按 `PromptBlock.sectionId` 与条目类型分桶估算。
7. `src/trace/tap.ts`：AgentEvent 的第二订阅者，投影为 trace 事件与 TUI 调试摘要；审批决定与技能激活落 `domain_fact`。
8. `src/trace/reader.ts`/`render.ts`/`export.ts`/`retention.ts`：坏行容忍读取、逐轮渲染、脱敏导出、保留期清理。
9. `src/usage/recorder.ts`/`stats.ts`：JSONL 追加与按名称聚合。
10. `src/cli/commands/`：trace/usage/sessions 三个只读子命令与共用 tail 助手。

## 4. 实现任务

1. 日志层。检查项为级别过滤、按天滚动、脱敏联动、`--log-level` 覆盖。
2. trace 写入。检查项为会话分文件、队列满降级、续写、坏行跳过。
3. runner 新事件。检查项为每轮 `request_prepared`、重试序列完整、压缩事实入流。
4. 组成分析。检查项为桶边界正确、估算与真实差值入流。
5. CLI 命令。检查项为 show 渲染与执行事实一致、export 默认 grep 不到密钥、tail 只输出完整行。
6. 调试面板。检查项为 Ctrl+T 切换、事件随状态发布刷新。

## 5. 验证

```powershell
npm run check
node dist/bin/bitori.js trace show <sessionId>
node dist/bin/bitori.js usage stats
node dist/bin/bitori.js sessions list
```

真实终端走查：启动 Bitori 完成一次含工具调用与技能激活的对话，随后 `trace show` 应能看到每轮请求规模、响应文本、工具调用与审批决定。

## 6. 常见坑

- 观察代码绝不能加入控制器的持久化屏障：tap 的所有方法必须火后不理，否则 trace 写盘变慢会直接拖住 agent loop。
- trace 与日志都要过脱敏器，但脱敏必须在 JSON 序列化之后做整行替换，避免逐字段遍历遗漏嵌套载荷。
- 工具定义每轮全量记录会迅速膨胀 trace；按 sha256 摘要去重，只在变化时携带完整定义。
- 估算 token 与 provider 真实值必然有差值（工具调用包装、协议开销），把差值本身记录下来比假装估算准确更有教学价值。
- 测试不可写路径不能用 `/proc` 等特殊目录——本机内核上递归 `mkdirSync` 会挂死而不是快速失败，用 chmod 只读目录构造确定性失败。

## 实现快照与设计决策

> 以下为本课（s15）完成时点的实现快照；后续课次可能已替换或扩展对应实现。

### 阶段结果

为既有内存态 AgentEvent 流补齐持久化与观察面：日志层、请求级 trace、上下文组成、使用统计、CLI 观察命令与 TUI 调试面板。

### 设计

- 单通道事件流：runner 新增的三类事件与既有 17 类事件走同一生成器，控制器 `#consume` 循环里 tap 同步投影（约 3 行改动），投影器对新事件天然穿透。
- trace 独立于 SQLite：JSONL 追加写与存储 Worker 分离，坏行容忍、生成路径永不重命名，回放不依赖数据库。
- 组成分析的桶由 `PromptBlock.sectionId` 标识（本课为 PromptBlock 增加可选字段），固定七模块合桶为 `fixed_system`，可选模块按 id 单独成桶。
- 使用统计不复用 s09 的 `CommandUsageTracker`（其仅测试引用），而是对齐外部 skill-tracker 的 JSONL 行格式，便于未来共用 dashboard；s09 的 tracker 已随之删除（见第 09 课补记）。
- 观测面由组合根显式开启：`ChatController` 构造参数注入 `observability.{traceDirectory, usagePath}`，缺省完全关闭——测试因此不会写用户主目录（评审发现的污染问题已借此修复）。
- 全局 Redactor 由组合根在 `setupLogging` 中注入，日志与 trace 共用同一实例；provider 错误展示沿用 s01 的 `redactSecrets`。

## 历史验证记录

### 验证记录

- `npm run check`（typecheck + lint + 279 tests + build）：通过。
- 集成验证：一次含 429 重试的 run 产出可回放 trace，重试序号/退避/错误码可从 JSONL 还原（`tests/integration/trace-run.test.ts`）。
- CLI 走查：`--help` 列出全部子命令；`trace show` 对合成 trace 正确渲染头部、领域事实、逐轮请求/重试/组成/响应与 token 趋势表；`trace export` 输出 7 个事件并标注已脱敏；非法子命令返回退出码 2。

## 与参考课程差异

参考实现中 trace 属于商业化产品的遥测层（OTel 导出、云端面板）。Bitori 坚持本地优先：JSONL 即数据契约，`--json` 输出可直接被脚本与 `benchmarks/` 消费；OTel 等外部导出器留待后续状态按需接入。
