# 第 13 课：Git Worktree 并行隔离

- 前置：第 12 课。
- 结果：Bitori 可在 `.bitori/worktrees/<slug>` 创建独立 Git 工作树，复制本地设置、链接依赖、检测变更并安全删除。
- 预计：6-8 小时。
- 环境：需要 git CLI；单测使用临时仓库。

## 1. 为什么学这一课

SubAgent 隔离了上下文，但没有隔离文件系统。两个 Agent 同时改同一个工作目录会互相覆盖。Git Worktree 提供空间维度隔离：共享对象库、各自分支、各自目录。

## 2. 能力规格

- slug 只允许字母、数字、下划线、连字符，长度 1～64，防路径遍历。
- Worktree 创建在 `.bitori/worktrees/<slug>`，分支名 `worktree-<slug>`。
- 目录已存在时快速恢复，不再次执行 `git worktree add`。
- 创建后 best-effort：复制 `.bitori`（排除 worktrees）、链接 `node_modules`、按 `.worktreeinclude` 复制被忽略文件。
- 纯文件系统读取 `.git`、HEAD、loose/packed refs；失败才回退 git 命令。
- 变更保护：`git status --porcelain` 非空或 HEAD 变化即视为有变更。
- 删除前校验路径必须在主仓内；`worktree remove --force` 后清理分支。
- Worktree 提示要求模型后续所有路径显式使用绝对路径，不切换进程 cwd。
- 不做跨 Worktree 合并策略和代码同步。

## 3. 代码走读

1. `src/worktree/worktree.ts`：slug 校验、git 根解析、HEAD 读取、创建/列表/删除、变更检测、创建后设置。
2. 后续接入：AgentDefinition `isolation: worktree` 与 Enter/ExitWorktree 工具。

## 4. 实现任务

1. 实现 slug 与 SHA 校验。检查项为非法路径拒绝。
2. 实现 HEAD 纯文件读取。检查项为 SHA-1/SHA-256 分支解析。
3. 实现生命周期。检查项为创建、恢复、列表、删除。
4. 实现创建后设置。检查项为配置复制、依赖链接、include 文件。
5. 实现变更保护。检查项为未提交修改与 HEAD 变化均返回 true。

## 5. 验证

```powershell
npm run typecheck
npm test -- tests/unit/worktree/worktree.test.ts
```

## 6. 常见坑

- Worktree 目录放在 `.bitori` 内时，复制配置必须排除 worktrees，否则父目录复制进自身。
- 未跟踪的本地设置也按“有变更”保守处理，避免误删用户配置。
- 不要用 `chdir` 切换目录；显式 cwd 才能避免路径缓存串目录。

## 实现快照与设计决策

> 以下为本课（s13）完成时点的实现快照；后续课次可能已替换或扩展对应实现。

### 阶段结果

为并行 Agent 提供同仓库下的独立文件系统，创建、恢复、变更保护和清理形成完整生命周期。

### 设计

- Worktree 根目录 `.bitori/worktrees/<slug>`；slug 白名单 `[A-Za-z0-9_-]{1,64}`。
- 创建使用 `git worktree add -b worktree-<slug> <path> HEAD`；目录已存在时快速恢复。
- 创建后设置：复制 `.bitori`（排除 worktrees）、symlink `node_modules`、按 `.worktreeinclude` 复制忽略文件；全部 best-effort。
- HEAD 读取优先解析 `.git` 指针、HEAD、loose ref、packed-refs 与 commondir，减少 git 子进程调用。
- 变更检测综合 porcelain status 与 HEAD 差异；任何异常保守返回 true。
- 删除时强制路径必须在 git root 下，先移除 worktree，再删除分支。
