# 第 11 课：Hook 生命周期系统

- 前置：第 10 课。
- 结果：Bitori 可在生命周期节点执行 command/prompt/http 动作，并能在工具执行前基于参数拦截。
- 预计：7-9 小时。
- 环境：无外部依赖。

## 1. 为什么学这一课

格式化、危险命令拦截、固定上下文注入的共同点是：触发条件明确、动作固定。Hook 把这些自动化从人工盯守变成生命周期规则。

## 2. 能力规格

- 事件覆盖会话、轮次、消息、工具与系统层：`session_start/end`、`turn_start/end`、`pre_send`、`post_receive`、`pre/post_tool_use`、`startup/shutdown/error/compact/permission_request/file_change/command_execute`。
- Hook 由事件、条件、动作组成；条件可省略。
- 条件支持 `==`、`!=`、`=~`、`~=`，`&&` 与 `||` 不可混用。
- 上下文变量：`$EVENT`、`$TOOL_NAME`、`$FILE_PATH`、`$MESSAGE`、`$ERROR`、`$TOOL_ARGS.xxx`。
- 动作支持 command、prompt、http、agent 占位。
- 执行控制支持 `once`、`async`、command timeout；`pre_tool_use` 不允许 async。
- prompt 输出进入通知队列，下一轮作为请求级提醒注入。
- 拦截事件返回拒绝原因，作为工具结果反馈给模型。
- 配置校验：事件名合法、动作必填字段完整、拦截约束正确。
- once 只做运行时标记，不做持久化。

## 3. 代码走读

1. `src/hooks/types.ts`：事件常量、HookConfig、HookContext、HookResult。
2. `src/hooks/engine.ts`：条件解析与求值、变量展开、四类动作、once/async、通知队列。
3. 后续接入点：`AgentRunner` 的 run/iteration/tool 生命周期与 `SafetyBatchScheduler` 执行前拦截。

## 4. 实现任务

1. 实现条件解析。检查项为四种操作符与逻辑约束测试。
2. 实现执行引擎。检查项为 command、prompt、once、reject 测试。
3. 实现配置校验。检查项为非法事件、缺失字段、async 约束测试。
4. 接入 Agent 生命周期。检查项为 Hook 输出能进入下一轮 reminder。

## 6. 常见坑

- `pre_tool_use` 拦截必须同步完成，否则工具调度无法知道是否继续。
- 正则条件建议用后缀匹配；glob 的 `*` 不跨目录分隔符，容易误判。
- Hook 失败不能拖垮主流程，错误要变成可观测结果。

## 实现快照与设计决策

> 以下为本课（s11）完成时点的实现快照；后续课次可能已替换或扩展对应实现。

### 阶段结果

提供事件 + 条件 + 动作的自动化规则引擎，支持命令执行、提示注入、HTTP 通知与工具前拦截。

### 设计

- `src/hooks/types.ts` 定义 15 个生命周期事件与 Hook 配置。
- `src/hooks/engine.ts` 实现条件解析（==/!=/=~/~=，&&/|| 二选一）、变量展开、command/prompt/http/agent 四类动作。
- `once` 用运行时 Set；`async` 只后台执行不等待；`pre_tool_use` 禁止 async。
- prompt 输出进入 notifications，消费方 drain 后作为下一轮 system reminder。
- 拦截语义：`reject: true` 时 Hook 输出成为工具拒绝原因，反馈给模型调整策略。
