# 第 06 课：MCP 工具客户端

- 前置：第 05 课。
- 结果：Bitori 启动时连接用户级与项目级配置的 MCP Server，发现远端工具并接入统一注册、权限、审批与执行链路。
- 预计：7-9 小时。
- 环境：一个可信 stdio Server 和一个 Streamable HTTP Server；HTTP 验收需分别准备 JSON 与 SSE POST 响应。

## 1. 为什么学这一课

Bitori 的能力不能只靠内置工具。MCP 让学生把外部工具发现、协议握手、传输差异和故障隔离接到既有系统，而不为 MCP 改出一条特殊链路。

## 2. 能力规格

- 用户级与项目级 `mcp_servers` 合并，同名项目项完整覆盖用户项。
- 协议版本 2025-06-18；initialize、notifications/initialized、分页 tools/list、tools/call。
- stdio 使用本地子进程和换行分隔 JSON-RPC；Streamable HTTP 每消息 POST，支持 JSON/SSE、session id 和协议版本 header。
- 工具公开名 `mcp__<server>__<tool>`；保留远端 description 与 inputSchema。
- 单个 Server 失败只告警自身，不影响其他 Server。
- MCP 工具默认视为有副作用，继续经过 Plan 过滤、权限档位和人在回路。
- 应用退出时统一关闭连接；stdio 子进程结束，HTTP 尽力 DELETE。

## 3. 代码走读

1. `src/config/loader.ts`、`src/config/schema.ts`：mcp_servers 合并与校验。
2. `src/mcp/json-rpc.ts`：id 配对、乱序响应、错误、超时、取消、关闭。
3. `src/mcp/stdio-transport.ts`、`src/mcp/http-transport.ts`：两种传输与帧格式。
4. `src/mcp/client.ts`：握手、分页发现、调用与缓存。
5. `src/mcp/manager.ts`：多 Server 并发、故障隔离与统一关闭。
6. `src/mcp/tool-adapter.ts`：远端工具到统一 Tool 契约。
7. `src/tools/registry.ts` 与权限链路：注册名冲突、半注册保护和审批复用。

## 4. 实现任务

1. 扩展配置与合并语义。检查项为覆盖、变量展开和缺失密钥显错测试通过。
2. 实现 JsonRpcPeer。检查项为乱序、错误、超时、取消、关闭测试通过。
3. 实现 stdio 传输。检查项为子进程启动、换行帧和退出清理测试通过。
4. 实现 HTTP 传输。检查项为 JSON/SSE、session header 和 DELETE 测试通过。
5. 实现客户端握手与分页。检查项为 initialize 顺序和 cursor 分页测试通过。
6. 实现管理与适配。检查项为命名冲突、故障隔离、工具调用测试通过。
7. 完成真实 Server 走查。检查项为本课 checklist 全项有真实结果。

## 5. 检查点

### 自动验证

```powershell
npm run check
node dist/bin/bitori.js --help
```

### 人工验收

配置一个真实 stdio 与一个 Streamable HTTP Server；验证工具发现、调用、审批、拒绝续跑、故障隔离和退出清理。结果记录到本课 `checklist.md`。

## 6. 常见卡点

- 信任远端 annotation 自动放行：一律按有副作用处理，安全默认不妥协。
- 一个 Server 阻塞启动：并发连接，但单项失败只影响自身。
- 注册名冲突留下半状态：先完成完整验证，再原子注册。
- 忘记清理子进程：manager 统一关闭，退出钩子要可重复执行。

## 7. 延伸与边界

本课不实现 resources、prompts、sampling、健康检查、自动重连、OAuth、热更新或旧 HTTP+SSE 兼容。完成本课后，学生已具备按同样模式扩展协议面的基础。
