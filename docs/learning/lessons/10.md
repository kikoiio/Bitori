# 第 10 课：Skill 系统

- 前置：第 09 课。
- 结果：Bitori 支持用 Markdown 声明可复用技能，启动时只注入目录，激活后把 SOP 钉进环境上下文。
- 预计：7-9 小时。
- 环境：无外部依赖。

## 1. 为什么学这一课

重复出现的操作（提交、审查、测试）不应该每次重新描述。Skill 把 SOP 文件化，用户可编辑、可版本化，Agent 可按需加载。

## 2. 能力规格

- Skill 由 YAML frontmatter 与 Markdown 正文组成。
- frontmatter 字段：`name`、`description`、`allowed-tools`、`mode`、`fork-context`、`model`。
- `mode` 支持 `inline` 与 `fork`；未知值回退 inline。`fork-context` 支持 `none/recent/full`，未知值回退 none。
- 加载顺序：`~/.bitori/skills` → `.bitori/skills`，项目级同名覆盖用户级。
- 支持单文件 Markdown 与目录型 `SKILL.md`。
- 启动目录只含 name、description、source；执行前重读源文件实现热更新，读失败回退缓存。
- `$ARGUMENTS` 支持内联替换；无占位时参数追加末尾。
- `ActiveSkills` 保持激活顺序，可同时激活多个并渲染到环境上下文。
- 坏单个 Skill 跳过，不阻断目录扫描。
- 不做 Skill 市场分发与版本管理。

## 3. 代码走读

1. `src/skills/types.ts`：Skill 元数据与来源类型。
2. `src/skills/parser.ts`：frontmatter 分离、字段校验、模式归一化。
3. `src/skills/loader.ts`：两级扫描、目录型布局、热更新、参数渲染。
4. `src/skills/executor.ts`：ActiveSkills 状态与 inline 执行。

## 4. 实现任务

1. 实现解析器。检查项为字段、非法模式回退、缺 name 报错。
2. 实现加载器。检查项为两级覆盖、目录型、热更新。
3. 实现激活状态。检查项为多 Skill 同显与参数替换。
4. 接入 LoadSkill 工具与 `/skill list|info|reload`。

## 5. 验证

```powershell
npm run typecheck
npm test -- tests/unit/skills/skills.test.ts
```

## 6. 常见坑

- 启动阶段不要读全部 body，否则目录注入会变成上下文负担。
- 热更新失败必须回退缓存，而不是让 Skill 消失。
- `allowed-tools` 只是候选白名单，最终仍要经过权限系统。
