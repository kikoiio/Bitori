# 第 05 课：五层权限系统

- 前置：第 04 课。
- 结果：每次工具调用先经过黑名单、路径沙箱、三层规则、权限档位和人在回路的统一判定，结果只有放行、询问、拒绝三态。
- 预计：7-9 小时。
- 环境：同第 04 课；需要验证本地 YAML 规则与审批交互。

## 1. 为什么学这一课

工具越多，权限越不能散落在工具实现里。本课把安全判定抽成与 TUI、模型和存储解耦的引擎，学生将学习安全边界集中化、规则合并和可解释的拒绝原因。

## 2. 能力规格

- run_command 黑名单硬拒绝递归强删、格式化/分区、关机重启、高危注册表写入、禁用安全组件、下载执行。
- 文件调用先解析真实路径；工作区外或链接逃逸返回 sandbox 拒绝。
- 三层规则文件：用户级 `~/.bitori/permissions.yaml`、项目级 `<workspace>/.bitori/permissions.yaml`、本地级 `<workspace>/.bitori/permissions.local.yaml`。
- 规则包含 tool、pattern、decision；合并后按 deny > ask > allow 决定。
- 三档：strict 所有调用询问但不采纳 allow；default 保持只读自动、副作用询问；bypass 自动放行但黑名单、沙箱、显式 deny 仍拒绝。
- `/permissions strict|default|bypass` 切换档位；会话放行留在内存，永久放行写入本地 YAML。
- 拒绝作为工具结果回写模型，Agent Loop 继续运行。

## 3. 代码走读

1. `src/tools/permission-engine.ts`：判定管线、规则合并与错误配置显错。
2. `src/tools/workspace-paths.ts`：真实路径沙箱的底层保证。
3. `src/tools/executor.ts`：绕过调度器直接执行时的兜底校验。
4. `src/agent/safety-batch-scheduler.ts`：ask 才进入审批，Y/S/P/N 决定。
5. 存储与 TUI：权限档位状态和审批界面。
6. `tests/unit/tools/permission-engine.test.ts`：先读测试反推规则语义。

## 4. 实现任务

1. 定义三态判定与错误码。检查项为放行、询问、拒绝测试通过。
2. 实现黑名单。检查项为六类危险命令均拒绝且无法被 allow 覆盖。
3. 实现沙箱优先。检查项为规则尝试放行工作区外路径仍被拒绝。
4. 实现三层规则读取与合并。检查项为缺失、非法、多文件优先级测试通过。
5. 实现三档与命令切换。检查项为档位语义和持久化测试通过。
6. 接入审批链路。检查项为本次、会话、永久放行和拒绝行为符合预期。
7. 更新 README 与人工场景。检查项为风险、路径和配置格式真实准确。

## 5. 检查点

### 自动验证

```powershell
npm run check
node dist/bin/bitori.js --help
```

### 人工验收

分别配置用户、项目和本地规则；验证黑名单、沙箱、三档切换、Y/S/P/N 和非法配置显错。结果记录到本课 `checklist.md`。

## 6. 常见卡点

- 在工具内再判一次权限：工具只执行；判定集中在引擎和 executor 兜底。
- 规则优先级按文件层排序：合并后 decision 优先，层级不参与优先级。
- bypass 变成无限制：黑名单、沙箱和显式 deny 必须仍然生效。
- 永久规则写错文件：只写本地级，不修改用户或项目规则。

## 7. 延伸与边界

本课只管本地内置工具。外部 MCP 工具默认有副作用，也复用这条链路；MCP 协议与传输在第 06 课实现。
