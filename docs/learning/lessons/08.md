# 第 08 课：跨会话记忆

- 前置：第 07 课。
- 结果：Bitori 启动时自动加载用户与项目指令文件，回合结束后可异步提取四类长期记忆，并在下次会话注入轻量索引。
- 预计：7-9 小时。
- 环境：无需真实模型即可完成单测；自动提取建议用一个低成本模型做人工验收。

## 1. 为什么学这一课

会话内压缩解决“装不下”，跨会话记忆解决“下次不记得”。编码 Agent 需要记住两类信息：项目事实（技术栈、架构、约束）和用户偏好（回复风格、纠正反馈）。这些信息应该有明确的文件形态，而不是藏在数据库里。

## 2. 能力规格

- 指令文件按用户级 `~/.bitori/BITORI.md`、项目级 `.bitori/BITORI.md`、项目根 `BITORI.md` 顺序发现。
- 支持 `@include path` 展开模块化内容；最大深度 5，`visited` 防环，路径不得跳出项目目录。
- 记忆分 `user`、`feedback`、`project`、`reference` 四类，以带 frontmatter 的 Markdown 文件保存。
- 用户级记忆写入 `~/.bitori/memory/`，项目级写入 `.bitori/memory/`。
- 索引 `MEMORY.md` 最多 200 行、25KB；请求前只注入索引，正文由模型按需读取。
- 提取器在自然停止的回合后运行，模型输出 `NONE` 时不落盘；并发提取合并，不重复写索引。
- 不做向量数据库、RAG 检索和团队记忆同步。

## 3. 代码走读

1. `src/memory/instructions.ts`：三层发现、`@include` 展开、越界与环路保护。
2. `src/memory/manager.ts`：frontmatter 解析、双目录读写、轻量索引与清理。
3. `src/memory/extractor.ts`：四类记忆标记解析、NONE 短路、并发合并。
4. 既有 `src/storage/`：Bitori 已用 SQLite + Worker 实现课程中 JSONL 存档的崩溃安全目标，本课不重复造存储。

## 6. 常见坑

- 记忆注入不能每轮变化，否则破坏上下文压缩后的缓存前缀。
- 用户级记忆不能写进项目目录，否则个人偏好会被提交到仓库。
- 索引必须限行限字节，否则“长期记忆”会变成新的上下文炸弹。

## 实现快照与设计决策

> 以下为本课（s08）完成时点的实现快照；后续课次可能已替换或扩展对应实现。

### 阶段结果

让 Bitori 拥有跨会话的项目知识与用户偏好：启动时加载指令文件，回合后提取长期记忆，下次会话注入轻量索引。

### 设计

- 指令文件三层发现：`~/.bitori/BITORI.md` → `.bitori/BITORI.md` → 项目根 `BITORI.md`。`@include` 最大深度 5、visited 防环、路径限制在项目内。
- 记忆文件按 scope 分目录：用户级 `~/.bitori/memory/`，项目级 `.bitori/memory/`。每条一个 Markdown，frontmatter 记 `name`、`description`、`type`。
- `MEMORY.md` 是唯一注入请求的索引，最多 200 行、25KB。
- `MemoryExtractor` 支持四类标记，`NONE` 静默；并发提取合并，完成后重建索引。
- 课程中的 JSONL 会话持久化在 Bitori 已由 SQLite Worker 覆盖（追加事务、崩溃恢复、列表元数据），本阶段不重复实现。
