# 第 04 课：系统提示与缓存通道

- 前置：第 03 课。
- 结果：Bitori 用七个稳定模块加环境信息构造系统提示，为 Anthropic 建立可缓存前缀，并按节奏注入 Plan 提醒。
- 预计：6-8 小时。
- 环境：同第 03 课；缓存验证建议使用支持显式 cache_control 的 Anthropic 端点。

## 1. 为什么学这一课

没有系统提示时，模型不知道工具优先级、编辑前读取和当前模式。随机加提示又会破坏前缀缓存。本课学习把“稳定规则”和“会话变化信息”分层，并把规则同步到工具描述，形成双重强化。

## 2. 能力规格

系统提示由七个固定模块构成：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出。会话激活时附加冻结的工作区、系统、Node、日期、profile 与模型信息。稳定块加 Anthropic cache_control；环境块不加。PLAN 模式第 1、4、7 轮注入完整提醒，其余轮次注入精简提醒；提醒是请求级上下文，不持久化、不显示。OpenAI 两协议走服务端自动前缀缓存。

## 3. 代码走读

1. `src/prompt/builder.ts`：PromptBlock、PromptSection 与优先级拼装。
2. `src/prompt/sections.ts`：七个模块正文与长度上限。
3. `src/prompt/environment.ts`：会话激活时采集并冻结环境。
4. `src/prompt/reminders.ts`：模式、轮次与完整/精简文本。
5. `src/chat/agent-controller.ts`：冻结时机与 Plan 轮次推导。
6. `src/agent/runner.ts`：把系统提示与提醒传入每次请求。
7. Providers：system/instructions 通道、cache_control 位置与缓存用量解析。

## 4. 实现任务

1. 建立提示模型与拼装器。检查项为优先级、空行、长度和确定性测试通过。
2. 固定七个模块正文。检查项为中文规则包含工具优先、先读后写、路径查证。
3. 冻结环境信息。检查项为会话激活后时间与 profile 变化不影响已冻结提示。
4. 接入三协议 system 通道。检查项为无 system 回归与 reminder 渲染测试通过。
5. 加 Anthropic 缓存断点并解析用量。检查项为工具末位与稳定块断点位置正确。
6. 实现 Plan 提醒节奏。检查项为五轮序列、/do 停止、再入重置和不持久化测试通过。
7. 更新工具描述与 README。检查项为关键规则在提示与工具描述中一致。

## 5. 检查点

### 自动验证

```powershell
npm run check
node dist/bin/bitori.js --help
```

### 人工验收

用真实端点验证两轮以上请求的缓存命中增长；四场景走查优先工具、先读后改、PLAN 只读与 DO 全工具。结果记录到本课 `checklist.md`。

## 6. 常见卡点

- 缓存命中率波动：检查稳定块是否逐字节一致，尤其提醒是否被写入持久历史。
- 环境信息加缓存标记：环境块变化会击穿稳定前缀。
- 提醒显示在聊天里：提醒只属于当次请求上下文，不是用户或助手消息。
- 工具描述与系统提示冲突：两处必须同步修改，并用测试锁定关键句。

## 7. 延伸与边界

本课不实现自定义指令、Skill 和长期记忆，只留扩展位。权限仍沿用 s02 的自动/询问分支；统一权限引擎在第 05 课实现。
