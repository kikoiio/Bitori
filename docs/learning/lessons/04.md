# 第 04 课：系统提示与缓存通道

- 前置：第 03 课。
- 结果：Bitori 用七个稳定模块加环境信息构造系统提示，为 Anthropic 建立可缓存前缀，并按节奏注入 Plan 提醒。
- 预计：6-8 小时。
- 环境：同第 03 课；缓存验证建议使用支持显式 cache_control 的 Anthropic 端点。

## 1. 为什么学这一课

没有系统提示时，模型不知道工具优先级、编辑前读取和当前模式。随机加提示又会破坏前缀缓存。本课学习把“稳定规则”和“会话变化信息”分层，并把规则同步到工具描述，形成双重强化。

## 2. 能力规格

系统提示由七个固定模块构成：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出。会话激活时附加冻结的工作区、系统、Node、日期、profile 与模型信息。稳定块加 Anthropic cache_control；环境块不加。PLAN 模式第 1、4、7 轮注入完整提醒，其余轮次注入精简提醒；提醒是请求级上下文，不持久化、不显示。OpenAI 两协议走服务端自动前缀缓存。

## 3. 代码走读

1. `src/prompt/builder.ts`：PromptBlock、PromptSection 与优先级拼装。
2. `src/prompt/sections.ts`：七个模块正文与长度上限。
3. `src/prompt/environment.ts`：会话激活时采集并冻结环境。
4. `src/prompt/reminders.ts`：模式、轮次与完整/精简文本。
5. `src/chat/agent-controller.ts`：冻结时机与 Plan 轮次推导。
6. `src/agent/runner.ts`：把系统提示与提醒传入每次请求。
7. Providers：system/instructions 通道、cache_control 位置与缓存用量解析。

## 4. 实现任务

1. 建立提示模型与拼装器。检查项为优先级、空行、长度和确定性测试通过。
2. 固定七个模块正文。检查项为中文规则包含工具优先、先读后写、路径查证。
3. 冻结环境信息。检查项为会话激活后时间与 profile 变化不影响已冻结提示。
4. 接入三协议 system 通道。检查项为无 system 回归与 reminder 渲染测试通过。
5. 加 Anthropic 缓存断点并解析用量。检查项为工具末位与稳定块断点位置正确。
6. 实现 Plan 提醒节奏。检查项为五轮序列、/do 停止、再入重置和不持久化测试通过。
7. 更新工具描述与 README。检查项为关键规则在提示与工具描述中一致。

## 5. 检查点

### 自动验证

```powershell
npm run check
node dist/bin/bitori.js --help
```

### 人工验收

用真实端点验证两轮以上请求的缓存命中增长；四场景走查优先工具、先读后改、PLAN 只读与 DO 全工具。结果记入本课「历史验证记录」。

## 6. 常见卡点

- 缓存命中率波动：检查稳定块是否逐字节一致，尤其提醒是否被写入持久历史。
- 环境信息加缓存标记：环境块变化会击穿稳定前缀。
- 提醒显示在聊天里：提醒只属于当次请求上下文，不是用户或助手消息。
- 工具描述与系统提示冲突：两处必须同步修改，并用测试锁定关键句。

## 7. 延伸与边界

本课不实现自定义指令、Skill 和长期记忆，只留扩展位。权限仍沿用 s02 的自动/询问分支；统一权限引擎在第 05 课实现。

## 实现快照与设计决策

> 以下为本课（s04）完成时点的实现快照；后续课次可能已替换或扩展对应实现。

### 阶段结果

s04 把 Bitori 从「不发任何系统提示」升级为「结构化系统提示 + 缓存通道 + 运行时指令注入」。系统提示由七个固定模块（身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出）按优先级拼装，尾部接环境信息；稳定模块与工具定义走 Anthropic 显式缓存断点，环境信息与对话走消息通道；Plan 模式的补充指令以带 `<system-reminder>` 标签的请求级消息按轮次注入，不持久化、不在界面显示。

### 核心结构

- `src/prompt/builder.ts` 定义 `PromptBlock`（text + cacheable）、`PromptSection`（id + priority + text）、`SystemPrompt`，并按优先级拼装：七个固定模块合成首个 `cacheable: true` 稳定块，环境信息与可选模块各自成块且不参与缓存。优先级 10–110 间距编号，自定义指令（90）、Skill（100）、长期记忆（110）留扩展位，本步不接内容源。
- `src/prompt/sections.ts` 持有七个固定模块的中文正文常量；正文在会话内逐字节稳定，总量控制在约 4000 字符以内。
- `src/prompt/environment.ts` 在会话激活时采集并冻结工作区根目录、操作系统、Node 版本、日期、profile 与模型名。
- `src/prompt/reminders.ts` 生成带标签提醒：Plan 模式第 1 轮起每隔 3 轮（1、4、7……）注入完整指令，其余轮次注入一行精简提醒；execute 模式不注入。
- `src/chat/agent-controller.ts` 在 initialize / createSession / switchSession 时重建并冻结系统提示；发起回合时从 `agent_runs` 尾部连续 plan 模式 run 数推导 Plan 轮次（本次 run 已入库，计数即轮次；/do 产生的 execute run 天然打断序列）。
- `src/agent/runner.ts` 把冻结的系统提示传入每次模型请求，并把 reminders 追加为 `reminder` 上下文项（位于最后一条用户消息之后）；`src/agent/stream-collector.ts` 聚合缓存用量字段。

### 缓存通道

Anthropic 协议：末位工具一个 `cache_control` 断点覆盖全部工具定义，稳定系统块一个断点覆盖七个固定模块；环境信息块不标记，保证可缓存前缀在会话内逐字节稳定。`message_start` 上报的 `cache_creation_input_tokens` / `cache_read_input_tokens` 映射进 `Usage` 可选字段，经事件流累计，状态栏在命中数大于 0 时显示 `cache N`。缓存字段不持久化，SQLite 结构不变。

OpenAI Chat / Responses 两协议无显式缓存标记：系统提示全文分别放入首条 system 消息和 `instructions` 字段，依赖服务端自动前缀缓存；不解析也不展示其缓存数据。

### 提醒注入

`ModelContextItem` 新增 `reminder` 类型，三个 Provider 各自显式渲染为用户角色消息（消除 else 分支静默错转风险）。提醒只存在于当次请求的内存上下文：不写入 SQLite、不出现在界面消息列表、内容由模式与轮次确定性生成，会话恢复后按相同规则重建。

### 关键规则双重强化

系统提示的「工具使用」模块写入三条规则：优先使用专用工具而非 shell 命令、编辑任何文件前必须先读取、不猜测路径先查证。六个工具的描述同步补充与各自直接相关的规则表述；s02 旧描述按留痕规则保留在各文件块注释中。工具参数、能力与限制不变。

- **定性场景（E2E-3）：** 四场景全过，明细见 `tests/acceptance/scenarios.md` 的「实际结果」与「走查结论」。要点：编辑前必先读取（find_files → search_text → read_file → edit_file）、查找搜索不走 run_command、Plan 模式模型只用只读工具且提醒按节奏注入、`/do` 无提醒且六工具开放、输出为简洁中文加规范 Markdown。
