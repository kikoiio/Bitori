# 第 12 课：SubAgent 子任务分发

- 前置：第 11 课。
- 结果：Bitori 支持定义式子 Agent、多层工具过滤、后台任务通知与非交互执行循环。
- 预计：8-10 小时。
- 环境：无外部依赖。

## 1. 为什么学这一课

单个 Agent 的上下文会被探索、规划、执行全部塞满。子 Agent 让主对话只保留结论，把噪声隔离在子上下文中，同时用工具白名单控制权限。

## 2. 能力规格

- Agent 定义使用 frontmatter：name、description、tools、disallowed_tools、system_prompt、max_turns、model、permission_mode、background。
- 加载顺序：内置 → `~/.bitori/agents` → `.bitori/agents`；项目级同名覆盖。
- body 可作为 `initialPrompt`；description 缺省取 body 前 200 字符。
- 坏文件跳过，不阻断加载。
- 内置 `general-purpose`、`plan`、`explore`；plan/explore 禁止写入与命令工具。
- 工具过滤顺序：全局禁用 → 角色黑名单 → 后台白名单 → 角色白名单。
- `agent` 工具全局禁用，防止无限嵌套。
- 后台任务记录状态、结果、时间，完成后输出 `<task-notification>` 通知。
- 子 Agent RunToCompletion：无交互，收集最终文本并返回。
- 不做 Worktree 文件隔离、团队编排和跨会话任务持久化。

## 3. 代码走读

1. `src/subagents/types.ts`：AgentDefinition 与三个内置角色。
2. `src/subagents/loader.ts`：frontmatter 解析与三级加载。
3. `src/subagents/tool-filter.ts`：多层过滤与全局禁用集合。
4. `src/subagents/task-manager.ts`：后台任务状态与通知队列。
5. `src/subagents/spawn.ts`：非交互执行循环与事件透传。

## 4. 实现任务

1. 实现定义与内置角色。检查项为字段和只读限制。
2. 实现加载器。检查项为覆盖、回退、坏文件跳过。
3. 实现工具过滤。检查项为四层规则组合。
4. 实现任务管理。检查项为状态流转与通知。
5. 实现 spawn 循环。检查项为最终文本收集与错误上抛。

## 6. 常见坑

- 子 Agent 必须禁止再次调用 Agent 工具，否则会递归派生。
- 后台任务的超时和取消要共用同一个 AbortSignal。
- 定义式子 Agent 应从空上下文启动；Fork 才继承父历史。

## 实现快照与设计决策

> 以下为本课（s12）完成时点的实现快照；后续课次可能已替换或扩展对应实现。

### 阶段结果

让主 Agent 能把探索、规划等子任务交给独立上下文执行，完成后把结论回传主对话。

### 设计

- `AgentDefinition` 支持 frontmatter 工具白黑名单、模型、轮次、权限模式与初始提示。
- 加载顺序内置 → 用户级 → 项目级，项目级同名覆盖，坏文件跳过。
- 工具过滤四层防线：全局禁用 `agent`、角色黑名单、后台白名单、角色白名单。
- `TaskManager` 管理后台任务状态，完成或失败后生成 `<task-notification>`，由主循环作为请求级提醒消费。
- `spawnSubAgent` 当前实现非交互文本执行；接入 AgentRunner 工具调度后可复用该入口执行受过滤的工具链。
