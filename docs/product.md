# 产品目标与路线图

核对日期：2026-10-27。此文描述目标与当前状态；具体行为以源码和测试为准，参见 [架构](architecture.md)。

## 目标

Bitori 面向在本地软件工作区中与模型协作的用户：通过对话理解和修改项目，查看工具调用，在执行副作用前按权限规则作出决定，并在本地保留会话。跨平台终端是当前入口；适配不同模型协议、限制工作区文件访问和提供可排查的运行记录是主要约束。

## 状态和方向

| 方向 | 状态 | 依据与后续 |
|---|---|---|
| 终端交互、三种模型协议、会话 | 已实现 | `src/tui/`、`src/providers/`、`src/storage/`；供应商和平台实际表现仍需分别验收。 |
| 多轮工具、Plan/Do、权限、MCP | 已实现 | `src/agent/`、`src/tools/`、`src/mcp/`；命令和 MCP 不构成操作系统沙箱。 |
| 记忆、上下文压缩、扩展和可观察性 | 已实现基础能力 | `src/memory/`、`src/compact/`、`src/skills/`、`src/hooks/`、`src/trace/`；以实际代码为准。 |
| 自动化验收与模型兼容性 | 持续完善 | `tests/` 和 `.github/workflows/`；真实端点测试按需运行，不等同完整供应商认证。 |
| 桌面图形应用 | 开发中 | `src/desktop/` 有 Electron 入口、界面和 IPC；`package.json` 配置 Linux AppImage/deb 打包。运行、打包及平台支持尚需验证，发布计划和时间未确定。 |
| 多模态、云同步、会话导入、自动断点续跑 | 当前不支持 | 是否纳入后续版本尚未确定。 |

路线图表达方向，不代表承诺的发布日期或功能规格。变更前应明确目标、权限边界、平台支持和验收方法。
