# s05：五层权限系统

## 状态概览

s05 在 s04 的工具调度和审批链路前增加统一权限判定：危险命令黑名单、真实路径沙箱、三层 YAML 规则、权限档位和人在回路。每次调用最终只有放行、询问、拒绝三态；任何拒绝都作为工具结果回写模型，Agent Loop 继续运行。

## 核心实现

- `src/tools/permission-engine.ts` 是与 TUI、模型和存储解耦的权限引擎。黑名单只作用于 `run_command`，覆盖递归强制删除、格式化/分区、关机重启、注册表高危写入、禁用安全组件和下载执行六类命令。
- 文件调用在规则匹配前通过 `WorkspacePaths` 解析真实路径；工作区外路径和链接逃逸返回 `sandbox` 拒绝。`ToolExecutor` 也保留一次底层兜底校验，绕过 Agent 调度器的直接执行不能跳过黑名单或沙箱。
- 规则从用户级 `~/.bitori/permissions.yaml`、项目级 `<workspace>/.bitori/permissions.yaml` 和本地级 `<workspace>/.bitori/permissions.local.yaml` 读取。缺失文件按空规则处理，非法 YAML、工具名或结果值在启动时指出具体文件。
- 规则格式为 `rules` 数组，每项包含 `tool`、`pattern`、`decision`；命令模式匹配完整命令文本，文件模式匹配工作区相对路径，支持精确匹配和 glob。所有层合并后按 `deny > ask > allow` 决定，层级不参与优先级。
- `strict`、`default`、`bypass` 三档写入本地级 YAML。默认档保持 s04 行为：只读自动放行，写入和命令询问；严格档所有调用询问但不采纳 allow；放行档自动放行，但黑名单、沙箱和显式 deny 仍拒绝。可通过 `/permissions strict|default|bypass`（也支持 `/permission`、`/mode`）切换。
- `SafetyBatchScheduler` 在执行前调用引擎；ask 才发布审批请求，Y/S/P/N 分别代表本次、本会话、永久放行和拒绝。会话规则只留在内存，永久规则写入本地 YAML 并立即加入当前合并集合。

## 状态留痕

s05 新增实现使用 `[s05]` 注释；s01–s04 的旧实现没有删除，仍按原文件中的状态块注释保留。新增权限状态只扩展 `AppState`，不改变会话数据库结构；权限档位属于工作区本地配置，会话放行不持久化。

## 自动验证

权限引擎专项测试覆盖黑名单硬拦截、沙箱优先级、三层规则优先级、三档语义、永久规则持久化和非法配置显错；完成开发后以 `npm run check` 作为整体回归门槛。
